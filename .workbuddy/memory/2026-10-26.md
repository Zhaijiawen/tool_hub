## archive 创建压缩包报错（clone → undefined.size 两连击）
- 现象：点「创建压缩包」先报 `postMessage on MessagePort: [object Object] could not be cloned`，修掉后又报 `Cannot read properties of undefined (reading 'size')`。
- 两层根因（都在 `ArchiveTool.vue` 的 `createArchive()` 传参）：
  1. clone 层：`createFiles` 是 `ref([])`，`createFiles.value` 是 Vue reactive 代理**数组**，无法被 comlink `postMessage` 结构化克隆（与 OCR `selectedLangs.value` 同源 bug）。
  2. shape 层（克隆修掉后才暴露）：worker 的 `E.write` 期望 `files` 为 `Array<{file, pathname}>`，会 `e.reduce((a,{file:r})=>a+r.size+128)` 读 `element.file.size`。旧代码传裸 `File[]`，使 `element.file` 为 `undefined` → `undefined.size`。客户端的 `Archive.write({files,outputFileName,compression,format})` 内部 `a.writeArchive(files, compression, format, passphrase)`，故 files 必须是 `[{file}]`。
- 修复：`const plainFiles = createFiles.value.map((f) => ({ file: f }))` —— map 经 Vue rawIterator 返回普通数组（绕开代理），同时把裸 File 包成 `{file}`，pathname 省略时 worker 回退用 `file.name` 作条目名。
- 验证：纯 JS 取值/包壳，逻辑等价；未实机跑浏览器。尚未提交。

## archive 创建压缩包 0 字节 + `written bytes don't match file size`（根因修正）
- 现象：修掉 shape 后，选文件点创建，压缩包 0 字节，console 报 `Error occured while writing file, written bytes don't match file size`（来自 libarchive.wasm 内 C 绑定 `write_archive_file`，非 JS 抛错，故 UI 拿到 0 字节结果而非 catch 报错）。先前的「缓冲溢出」判断是**错的**——改了 1.1x 缓冲后仍复现，说明不是 size 估算问题。
- **真根因（已确认）**：UI 把 `compression` 值 `'deflate'` / `'store'` 直接传给 C 绑定 `start_archive_write(filter, format, ...)` → `archive_write_add_filter_by_name(a, filter)`。但 `'deflate'` 与 `'store'` **都不是 libarchive 合法的外部流过滤器名称**（合法名：none / gzip / bzip2 / xz / zstd / lz4 / lzma / compress …）。非法名使 `add_filter_by_name` 返回 `ARCHIVE_FATAL` 并使归档进入错误态，之后每次 `archive_write_data` 都返回 -1 → C 打该错误、归档写废 → 0 字节。默认 `zip + deflate` 因此**出厂即坏**。证据：① libarchive 源码 `archive_write_add_filter_by_name` 的 name 表里无 deflate/store；② 同包 `ArchiveCompression` 枚举里也根本没有 deflate/store（只有 none/gzip/bzip2/xz/zstd/lz4/…）。
- **关键语义**：ZIP/7Z 的压缩由**格式内置**处理（zip=deflate、7z=lzma），不需要也不应使用外部流过滤器；只有 TAR 是纯打包容器，才用外部过滤器（none/gzip/bzip2/xz/zstd/lz4）。所以 ZIP/7Z 必须传外部过滤器 `'none'`（透传），由格式内部压缩。
- 修复（双管齐下，都在 `ArchiveTool.vue`，外加 locale）：
  1. `compression` 默认 `'none'`；`compressionOptions` 改为合法过滤器名（none/gzip/bzip2/xz/zstd/lz4），删掉 deflate/store。
  2. `FORMAT_DEFAULTS` 三个格式 compression 全改 `'none'`。
  3. `createArchive()` 计算 `effectiveCompression = format==='tar' ? compression.value : 'none'`，ZIP/7Z 强制 `'none'`。
  4. 模板：压缩算法选择器仅 TAR 显示，ZIP/7Z 显示提示「{fmt} 使用各自内置压缩」。
  5. locale（zh/en）：`compDeflate/compStore` → `compNone` + 新增 `compBuiltin`；`infoContent` 改为描述正确语义。
  6. 保留 `worker-bundle.js` 的 1.1x 缓冲余量作为防御（无害，防不可压缩大文件溢出）。
- 验证：node 实跑 npm 包 `libarchive-node.mjs` 各组合——`deflate`/`store` 必 0 字节（确认非法），但 node worker_threads 的 File 传输在其它组合也偶发 0 字节（环境假象），故该 harness 不可靠；结论以 libarchive 源码 + 包枚举为准。浏览器用工件是 vendored `worker-bundle.js`（含 1.1x 缓冲修复），两处修复均生效。未实机跑浏览器，待用户本地验证。尚未提交。

## archive 创建侧彻底弃用 libarchive，改用 fflate（最终修复）
- **结论**：libarchive.js 2.0.2 的 write 路径对「标准归档」根本不可用——`filter=none` 虽合法却产出 0 字节；`gzip/bzip2/xz` 虽能出字节但成「过滤器包裹格式」双层文件（magic 是 GZIP 而非 PK），标准工具打不开。逐组合实测后确认无任一组合能产出标准 .zip/.tar。故**创建侧完全弃用 libarchive**，改用已装好的 `fflate@0.8.3`。
- 改动：
  1. `ArchiveTool.vue`：删除 `FORMAT_DEFAULTS` 及其 watch（曾引用已删常量，切格式必抛 ReferenceError）；`createArchive()` 改为 fflate `zip({level})`（zip→deflate level 6 / store level 0）与手写 ustar `buildTar`（tar→可选 gzipSync 包裹）；`compressionOptions` 仅 TAR 的 none/gzip；删除 7zip 创建单选（fflate 不支持 7Z）；新增 `createWarn` 软提示（超大输入，非硬拦截，fflate 无 wasm 内存上限）；create 按钮 `:disabled` 去掉 `wasmLoading`（创建不依赖 wasm）。
  2. 新增 `src/components/other/tar-writer.js`：手写 ustar，512 定长头 + 数据 512 对齐 + 末两零块 + 文件名>100B 走 GNU 长文件名扩展（typeflag 'L'）。抽出为独立模块便于单测。
  3. locale（zh/en）：删 `compDeflate/compStore/compBzip2/compXz/compZstd/compLz4`，`compBuiltin` 改为静态串；`createTooLarge`（硬拦截措辞）替换为 `createLargeWarn`（软提示）；`description`/`infoContent` 改写：解压仍 libarchive WASM，创建 fflate 标准 ZIP/TAR，创建无需下载 wasm。
- 验证（均为确定性，非浏览器假象）：
  - node harness：fflate `zip` 出 PK magic 且 `unzip` 回读 names+data 全匹配；`buildTar` 出 ustar magic、自写解析器校验 names+data+>100B 长文件名全匹配；`gzipSync(tar)` 出 gzip magic 且 `gunzipSync` 字节一致。**ALL PASS**。harness 跑完即删。
  - `@vue/compiler-sfc` 直接编译 `ArchiveTool.vue`：`template errors: []`，setup 绑定全部解析（含 buildTar/fflate/createWarn/syncDefaultExt）。
  - 全量 `vite build` 能跑完 transform+rollup 并到达 brotli/gzip closeBundle（证明全模块无编译错误）；仅末尾 `dist/assets` 清空（safe-delete bulk 守卫）与复制 `public/docs/...`（brokered-fs 守卫）被 WorkBuddy 沙箱拦截而中断——纯环境 fs 策略，非代码；用户本机 `npm run build` 正常。
