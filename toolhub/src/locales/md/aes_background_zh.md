# AES 技术背景

## 概述
高级加密标准（AES）是由美国国家标准与技术研究院（NIST）于2001年建立的对称分组密码算法。它被广泛用于保护敏感数据，并已成为全球加密的事实标准。AES基于比利时密码学家Joan Daemen和Vincent Rijmen开发的Rijndael密码。

## 历史与发展

### 起源
- **1997年**：NIST宣布AES竞赛以替代DES
- **1998年**：提交了15个候选算法
- **1999年**：选出5个决赛算法（MARS、RC6、Rijndael、Serpent、Twofish）
- **2000年**：Rijndael被选为获胜者
- **2001年**：AES正式发布为FIPS 197

### 选择标准
- 安全强度和抗密码分析能力
- 计算效率和性能
- 跨平台实现的灵活性
- 简单性和易于分析

## 核心架构

### 分组结构
AES操作固定大小的128位（16字节）分组。算法支持三种密钥大小：
- **AES-128**：128位密钥（10轮）
- **AES-192**：192位密钥（12轮）
- **AES-256**：256位密钥（14轮）

### 状态数组
128位分组被组织为称为状态数组的4×4字节矩阵：
```
[a00 a01 a02 a03]
[a10 a11 a12 a13]
[a20 a21 a22 a23]
[a30 a31 a32 a33]
```

### 密钥调度
密钥调度从原始密钥生成轮密钥：
- **密钥扩展**：为每个加密轮导出轮密钥
- **轮常量**：使用预定义的常量进行密钥扩展
- **密钥长度**：确定轮数和密钥调度复杂度

## 加密过程

### 主轮
每个加密轮由四个变换组成：
1. **SubBytes**：使用S盒进行非线性替换
2. **ShiftRows**：行的循环移位
3. **MixColumns**：列的线性变换
4. **AddRoundKey**：与轮密钥进行XOR运算

### 初始轮和最终轮
- **初始轮**：仅AddRoundKey变换
- **最终轮**：排除MixColumns变换
- **主轮**：应用所有四个变换

### 轮结构
```
初始轮：AddRoundKey
主轮：SubBytes → ShiftRows → MixColumns → AddRoundKey
最终轮：SubBytes → ShiftRows → AddRoundKey
```

## 关键变换

### SubBytes
- **S盒查找**：使用替换表替换每个字节
- **非线性**：提供抗线性密码分析能力
- **可逆**：每个S盒条目都有唯一的逆
- **数学基础**：在GF(2⁸)中使用乘法逆

### ShiftRows
- **第0行**：不移位（0个位置）
- **第1行**：左移1个位置
- **第2行**：左移2个位置
- **第3行**：左移3个位置

### MixColumns
- **矩阵乘法**：每列乘以固定矩阵
- **多项式算术**：在GF(2⁸)中的运算
- **扩散**：将输入变化扩散到输出
- **可逆**：矩阵具有乘法逆

### AddRoundKey
- **XOR运算**：状态数组与轮密钥进行XOR
- **密钥加法**：简单的按位异或
- **可逆**：解密使用相同操作

## 解密过程

### 逆变换
- **InvSubBytes**：逆S盒替换
- **InvShiftRows**：右移操作
- **InvMixColumns**：逆矩阵乘法
- **AddRoundKey**：与加密相同（XOR是自逆的）

### 轮顺序
解密按相反顺序应用变换：
```
初始轮：AddRoundKey
主轮：InvShiftRows → InvSubBytes → AddRoundKey → InvMixColumns
最终轮：InvShiftRows → InvSubBytes → AddRoundKey
```

## 安全特性

### 抗密码分析
- **差分密码分析**：通过S盒设计抵抗
- **线性密码分析**：通过非线性SubBytes保护
- **代数攻击**：复杂的多项式方程
- **侧信道攻击**：容易受到时序/功耗分析

### 密钥强度
- **128位**：对大多数应用足够
- **192位**：对敏感数据的增强安全
- **256位**：最高安全，推荐用于长期存储

### 数学特性
- **雪崩效应**：小的输入变化导致大的输出变化
- **完整性**：每个输出位依赖于所有输入位
- **平衡性**：输出值的均匀分布

## 实现考虑

### 性能优化
- **查找表**：预计算的S盒和逆S盒
- **位切片**：多个分组的并行处理
- **硬件加速**：专用AES指令（AES-NI）
- **内存使用**：速度和内存之间的权衡

### 平台支持
- **CPU指令**：现代处理器上的AES-NI
- **软件库**：OpenSSL、Crypto++、Bouncy Castle
- **硬件模块**：专用密码处理器
- **移动设备**：ARM处理器的优化实现

### 侧信道保护
- **恒定时间**：避免基于时序的攻击
- **功耗分析**：实现针对DPA的对策
- **缓存攻击**：防止缓存时序攻击
- **随机化**：添加熵以防止模式分析

## 操作模式

### 电子密码本（ECB）
- **简单模式**：直接分组加密
- **限制**：分组之间无扩散
- **用例**：单分组加密、密钥派生

### 密码分组链接（CBC）
- **链接**：每个分组与前一个密文进行XOR
- **初始化向量**：第一个分组的随机IV
- **特性**：提供扩散，需要顺序处理

### 计数器（CTR）
- **流密码**：将分组密码转换为流密码
- **并行化**：分组可以独立处理
- **随机数**：每次加密的唯一计数器值

### Galois/计数器模式（GCM）
- **认证加密**：提供机密性和真实性
- **关联数据**：支持额外的认证数据
- **性能**：高效的硬件实现

## 标准和合规

### FIPS 197
- **官方标准**：美国政府加密标准
- **规范**：完整的算法描述
- **验证**：政府使用必需

### ISO/IEC 18033-3
- **国际标准**：全球认可
- **兼容性**：可互操作的实现
- **认证**：商业产品必需

### 通用标准
- **安全评估**：正式安全评估
- **认证级别**：EAL1到EAL7
- **供应商验证**：独立安全测试
