# CIDR 和子网：这些数字到底什么意思

配过 VPC、设过路由器、盯过 AWS 安全组的人都跟 CIDR 打过交道。我们来拆一下这些数字背后的逻辑。

## IP 地址就是个 32 位整数

你天天敲的 `192.168.1.0`，本质是个 32 位二进制数，只不过用了人类好读的点分十进制写法。每个段 8 位：

```
192      .168      .1        .0
11000000 .10101000 .00000001 .00000000
```

所以 `192.168.1.0` 在十进制里等于 `3232235776`。没人这么数，但记住底层全是位运算就够了。

## 子网掩码把地址拆成网络和主机两部分

子网掩码也是 32 位，前面一串 `1` 后面一串 `0`：

```
255.255.255.0
11111111 . 11111111 . 11111111 . 00000000
```

- 掩码为 `1` 的位是网络部分
- 掩码为 `0` 的位是主机部分

`255.255.255.0` 表示前 24 位是网络，后 8 位是主机。这就是为什么这个网段有 254 个可用地址（256 减去网络地址和广播地址）。

## CIDR：斜杠记法

CIDR（无类域间路由）抛弃了老式的 A/B/C 类划分，直接用前缀长度：

```
192.168.1.0/24
```

`/24` 就是"前 24 位是网络部分"，跟 `255.255.255.0` 等价，写法更简洁。

## 常用前缀速查

| 前缀 | 子网掩码 | 可用主机数 | 典型用途 |
|---|---|---|---|
| /8 | 255.0.0.0 | 16,777,214 | 超大型私有网络 |
| /16 | 255.255.0.0 | 65,534 | 中型网络 |
| /24 | 255.255.255.0 | 254 | 家庭/办公局域网 |
| /25 | 255.255.255.128 | 126 | 把 /24 对半分 |
| /28 | 255.255.255.240 | 14 | 几台机器的小子网 |
| /30 | 255.255.255.252 | 2 | 路由器之间的点对点链路 |
| /32 | 255.255.255.255 | 1 | 单主机路由 |

## 网络地址和广播地址

网络地址是网段里最小的地址（主机位全 0）。不能分配给设备，它代表网络本身。

广播地址是网段里最大的地址（主机位全 1）。发到这个地址的包会送到子网里所有主机。

夹在中间的是可用主机地址，数量是 `2^(32 - 前缀) - 2`。

## 私有地址段（RFC 1918）

公网不路由的地址段：

| 段 | CIDR | 地址数量 |
|---|---|---|
| A 类 | 10.0.0.0/8 | 16,777,216 |
| B 类 | 172.16.0.0/12 | 1,048,576 |
| C 类 | 192.168.0.0/16 | 65,536 |

如果在公网环境里看到这些地址作为源地址，说明前面有 NAT。
