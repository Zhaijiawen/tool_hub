# 语音转文字：工作原理

## 浏览器为什么需要一个本地语音引擎

浏览器原生语音识别基本是条死路：

- **Web Speech API**（Chrome 的 `webkitSpeechRecognition`）会把音频上传到谷歌云端服务器——离线不可用，且毫无隐私可言
- **macOS / Windows 系统听写**只能在系统输入框内工作，无法处理文件
- 各类"上传后转写"的在线服务，意味着把会议录音、访谈、语音备忘交给别人的服务器

这个工具走第三条路：通过 WebAssembly 在浏览器里完整运行 **OpenAI 的 Whisper tiny 模型**。音频不离开你的设备，模型缓存后离线可用。

## 引擎：Whisper tiny + ONNX Runtime（WASM）

技术栈分三层：

1. **[Whisper tiny](https://github.com/openai/whisper)（int8 量化）**——OpenAI 的开源语音识别模型。tiny 版本约 3900 万参数，int8 量化后共 7 个文件约 41.6MB。体积小，但实测中、日、英转写均正确
2. **[transformers.js 2.17.2](https://github.com/huggingface/transformers.js)**——Hugging Face 的 JS 推理运行时，将模型封装为标准 `automatic-speech-recognition` pipeline
3. **[ONNX Runtime Web 1.19.2](https://onnxruntime.ai)**——通过 SIMD + 多线程 wasm 构建（约 10.5MB）执行 ONNX 计算图

推理在 **Web Worker** 中运行，长达数分钟的音频也不会卡住页面，且任何时候都可以取消——包括引擎和模型下载过程中。

## 它实际能做什么

**转写（保持原语言）**——自动检测语言并输出该语言的文本。喂一段日语播客，得到日语文字；英语会议，得到英语文字。也可以手动指定语言。

**翻译（为英文）**——Whisper 内置的翻译任务。任何语言的语音都输出为英文文本。我们端到端验证过：日语语音进，`"I'm going to give you a new video."` 出。这是给外语材料生成英文字幕最快的方式，无需额外的翻译步骤。

**时间戳 + SRT 导出**——片段级时间码，可导出为标准 `.srt` 字幕文件。

**长音频**——超过 30 秒自动切分为 30 秒窗口（带滑动上下文），且后续分块处理时中间结果实时回流。

## 诚实的边界

- **tiny 模型是小，不是魔法。** 语速正常的清晰语音效果良好；强背景噪音、多人交叠、重口音会明显抬高错误率。追求广播级质量，桌面 GPU 上的 large-v3 才是正解——本工具定位是浏览器本地方便性
- **速度约为实时的 1–3 倍。** 10 分钟录音通常几分钟内完成。请保持标签页在前台——浏览器会限制后台标签的算力
- **首次使用需下载约 52MB**（引擎 + 模型），之后有缓存；且已下载完成的文件会持久保留，重复使用只会补拉缺失文件
- **不是实时的。** 这是文件转写，不是麦克风流的实时听写

## 隐私与技术说明

- 全部推理本地完成。模型由本站自托管，运行时配置 `allowRemoteModels = false`——它永远不可能悄悄回源 Hugging Face
- 音频通过 Web Audio API 以 16kHz 单声道解码（Whisper 的原生输入格式），重采样与声道混合由浏览器完成
- 格式：MP3 / WAV / M4A / OGG / Opus / FLAC，以及任何带音轨的视频容器（提取音频，视频部分丢弃）
