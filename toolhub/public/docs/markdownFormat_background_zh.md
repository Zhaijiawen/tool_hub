# Markdown 格式化 — 幕后原理

Markdown 格式化器基于 **Prettier** 引擎，自动整理 Markdown 源码的排版，不改内容语义。

## 格式化器实际做了什么

Prettier 用 `markdown` parser 解析文档后，按以下规则整理：

- **表格对齐**：分隔符补全、列间加空格，让表格源码可读
- **空行规范化**：标题前补空行、多余的连续空行被压缩为一个
- **代码块留白**：围栏代码块前后自动加空行，避免贴邻文字
- **缩进整理**：嵌套列表的缩进对齐，消除不规则的缩进偏移

## 不会改什么

Prettier 的策略是「只排版，不改变语义」。以下内容**原样保留**：

- 段落内部的文字——不会自动折行（Markdown 段落没有宽度概念，折行可能破坏语义）
- 嵌套列表的符号——底层的 `*`/`+` 保持原样，不强制统一为 `-`
- 有序列表的数字——保持你写的数值，不自动递增或递减
- 链接 URL、图片路径——原样通过

理解这个边界很重要：Markdown 格式化做的是让文档**源码整齐**，不是做**内容编排**。它不会替你改写句子、调整段落长度，也不会改变任何一个列表符号背后的语义。

## 为什么选 Prettier

Prettier 是前端社区最广泛使用的代码格式化工具。它的 Markdown 支持覆盖了日常文档最影响可读性的几个维度：表格、空行、代码块。规则不可配置——所有人拿到的是同一套风格，团队协作时尤其有用。
