# DNS 查询工具 — 背后是什么

DNS 就是互联网的电话本。你输入 `example.com`，DNS 帮你查出浏览器真正需要连接的 IP 地址（比如 `93.184.216.34`）。没有 DNS，你得记住每个网站的 IP 地址。

## 解析过程

在浏览器输入一个域名，背后发生的事：

1. 浏览器和操作系统先翻本地 DNS 缓存——如果已经知道 IP，就不用联网查了
2. 缓存没有，就问你配置的 DNS 服务器（一般是路由器或运营商给的）
3. 这个服务器做递归查询：根域名服务器告诉它 `.com` 在哪、`.com` 顶级域服务器告诉它 `example.com` 的权威 DNS 在哪、权威服务器返回最终 IP
4. 每一跳都会按 TTL 缓存结果，下次直接返回

## 实际会用到的记录类型

| 记录类型 | 干什么的 |
|---------|---------|
| **A** | 域名到 IPv4 地址的映射，最常用 |
| **AAAA** | 同上，IPv6 版 |
| **CNAME** | 别名，`www.example.com` 指向 `example.com` 或 CDN 域名 |
| **MX** | 邮件服务器地址，邮件系统靠它路由 |
| **TXT** | 任意文本，SPF、DKIM、域名验证等都用它 |
| **NS** | 这个域名的权威 DNS 服务器是哪些 |
| **SOA** | 区域元信息——序列号、刷新间隔、管理员联系方式 |

## TTL 比你想象的更重要

TTL（秒）控制 DNS 缓存在重新查询之前保留记录多长时间。短 TTL（300 秒）意味着改了记录很快就生效，但你的 DNS 服务器查询压力大。长 TTL（86400 秒、一天）查询少，但改了记录得等很久才生效。

经典翻车场景：你改了一条 TTL 为 24 小时的 A 记录，改完马上查，看到还是旧 IP，慌了。正确的做法：改之前把 TTL 降到 300，改完确认生效后再提回去。

## DNS over HTTPS（DoH）

传统 DNS 走 UDP 53 端口，明文传输。你的运营商、咖啡店 WiFi、网络上任何人都能看到你在查什么域名。DoH 把 DNS 查询包在 HTTPS 里——和你的网银一样的加密级别。

这个工具用的是 Cloudflare 的 DoH 接口：

```
GET https://cloudflare-dns.com/dns-query?name={domain}&type={type}
Headers: Accept: application/dns-json
```

返回干净的 JSON。关键字段：`Status`（0 表示成功）、`Answer`（实际记录）、`AD`（DNSSEC 验证是否通过）。

## 常见 DNS 坑

**传播延迟** — 改了记录后，有些解析器马上看到新值，有些要等几小时。别急，这是正常现象，提前规划就好。

**DNSSEC** — 对 DNS 响应做数字签名，解析器可以验证没被篡改。一旦配置出错，你的域名就从互联网上消失了。

**DNS 污染/劫持** — 某些网络环境会拦截 DNS 查询返回假结果。用 DoH 可以绕过去，因为查询是加密的且直连可信解析器。
