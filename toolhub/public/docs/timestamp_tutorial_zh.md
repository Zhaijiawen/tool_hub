# 时间戳转换器 — 使用教程

时间戳转换器是双向桥梁：塞一个 Unix 时间戳进去，它给你人类可读的日期；给一个日期字符串，它吐出时间戳。还能在不同字符串格式之间互转。

## Unix 时间戳转日期

把 Unix 时间戳（秒）粘贴或输入到输入框里。转换器会显示对应日期和时间：本地时区版、UTC 版、以及几种常见格式。

如果你的时间戳是毫秒——也就是 JavaScript `Date.now()` 产出的那种——打开毫秒模式。转换器内部除以 1000，你不用自己算。如果你不小心把秒级时间戳放在毫秒模式下，会得到一个 1970 年的日期，这就是相当明显的提示了。

## 日期转时间戳

切到日期转时间戳模式，用选择器挑个日期时间。转换器算出 Unix 时间戳（秒）。你也可以直接粘贴 ISO 8601 字符串比如 `2024-04-09T14:30:00Z`，直接得到时间戳。

调 API 请求参数、设测试数据、或者想知道「下周二下午三点」到底是什么时间戳的时候，这个方向就很方便。

## 不同日期格式互转

格式转换器接收一个日期字符串然后重新格式化。从电子表格里拿到的 `MM/DD/YYYY` 格式，数据库要的是 `YYYY-MM-DD`？贴进来，设来源格式，设目标格式，转换。工具使用标准格式标记：

| 标记 | 含义 | 示例 |
|---|---|---|
| `YYYY` | 四位年份 | 2024 |
| `YY` | 两位年份 | 24 |
| `MM` | 两位月份 | 04 |
| `DD` | 两位日期 | 09 |
| `HH` | 两位小时（24时制） | 14 |
| `hh` | 两位小时（12时制） | 02 |
| `mm` | 两位分钟 | 30 |
| `ss` | 两位秒 | 00 |
| `A` | 上午/下午 | 下午 |

## 选择正确的输出时区

转换器默认用你的本地时区，但可以切到 UTC 或任意 IANA 时区（如 `America/New_York` 或 `Asia/Shanghai`）。跨时区团队协作时这一点至关重要——你得搞清楚「午夜」指的到底是 UTC 午夜还是本地午夜。

常用工作流：服务器日志全是 UTC，但你在排查一个用户反馈为「东部时间晚上 9 点」的问题。把用户的本地时间转成 UTC，然后在 UTC 时间戳附近翻日志。转换器帮你算了偏移量，不用自己记东部时间到底是 UTC-5 还是 UTC-4（夏令时影响）。

## 处理模糊输入

有时候你粘贴了东西但转换器不知道该拿它怎么办。数字 `1712620800` 可以是 Unix 时间戳，也可以是个 ID。缩写月份像 `Jan` 在英文里是 January，但在别的语言里可能另有含义。当输出看起来不对时：
- 检查你要的是秒还是毫秒模式
- 确认来源格式字符串与实际输入格式一致
- 确认时区设置
- 试试另一个转换方向——有时候数据该往哪个方向流会更清楚
