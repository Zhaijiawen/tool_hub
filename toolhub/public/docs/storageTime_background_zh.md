# 存储与时间转换器 — 数字背后的单位

## 存储：两套体系搞混就出问题

数字存储有两套前缀体系，听起来差不多但实际上不一样，搞混了就会出现「为什么我买的 1TB 硬盘插上显示只有 931GB」这种经典困惑。

**十进制（SI）** — 以 1000 为倍数，硬盘厂商用的：
- 1 KB = 1,000 字节
- 1 MB = 1,000,000 字节
- 1 GB = 1,000,000,000 字节
- 1 TB = 1,000,000,000,000 字节

**二进制（IEC）** — 以 1024 为倍数，操作系统用的：
- 1 KiB = 1,024 字节
- 1 MiB = 1,048,576 字节
- 1 GiB = 1,073,741,824 字节
- 1 TiB = 1,099,511,627,776 字节

买的 1TB 硬盘是 1,000,000,000,000 字节。Windows 用二进制显示容量，除以 1,073,741,824 得出 ~931 GiB。硬盘容量没缩水——是单位不一样。

## 时间单位

| 单位 | 等于几秒 |
|------|---------|
| 纳秒 (ns) | 0.000000001 |
| 微秒 (µs) | 0.000001 |
| 毫秒 (ms) | 0.001 |
| 秒 (s) | 1 |
| 分钟 (min) | 60 |
| 小时 (h) | 3,600 |
| 天 (d) | 86,400 |
| 周 (w) | 604,800 |
| 月（平均）| ~2,629,800 |
| 年（儒略年）| 31,557,600 |

## 实际场景中为什么重要

**网速 —** 运营商用 bps（位每秒）标速度，但文件大小按字节算。100 Mbps / 8 = 12.5 MB/s 实际速度。一个 1GB 文件按这速度要下约 80 秒。

**超时配置 —** Session 超时用毫秒、缓存 TTL 用秒、Token 过期用分钟或天。单位换算错一个 1000 倍，30 分钟的 session 就变成 30 秒了。

**数据库存储规划 —** 索引大小、行大小、列类型——都是从字节算起，到 MB 级别你就得跟云服务商谈存储层级了。
