# ECDSA 技术背景

ECDSA（椭圆曲线数字签名算法）是 DSA 的椭圆曲线版本。它是比特币、以太坊、TLS 证书和无数其他系统使用的签名方案。ECDSA 产生的签名能证明你拥有某个私钥而不泄露它，依赖椭圆曲线离散对数问题保证安全性。

## nonce 问题

ECDSA 有一个需要知道的致命漏洞：签名 nonce（通常叫 `k`）必须唯一、不可预测、且对同一个私钥绝不重复使用。如果你用同一个 `k` 和同一个私钥签了两条不同的消息，任何人都能用基础代数从两个签名中恢复你的私钥。

这在生产环境中真实发生过：PlayStation 3 的签名密钥因为在索尼的实现中使用了固定 `k` 值而被提取。多个比特币钱包因 nonce 重用攻击损失了资金。Android 的 Java `SecureRandom` 曾经有个 bug 导致产生可预测的 `k` 值，破坏了受影响设备上的 ECDSA。

现代实现使用 RFC 6979 确定性 ECDSA，它通过 HMAC 从私钥和消息哈希派生 `k`，从根本上杜绝了 nonce 重用。你应该用这种模式。

## 密钥和签名大小

256 位 ECDSA 密钥（P-256 曲线）提供约 128 位安全性。签名通常 DER 编码后 70-72 字节（标准格式），或原始 `r||s` 形式 64 字节。

对比 RSA：2048 位 RSA 密钥提供约 112 位安全性，产生 256 字节签名。ECDSA 的紧凑性优势非常明显。

## 选择曲线

和 ECDH 一样的曲线选择规则：

- **NIST P-256**：主力。每个库都支持。128 位安全性。
- **secp256k1**：比特币曲线。知名只是因为比特币的网络效应。
- **Ed25519**：如果从零开始，用 Ed25519 而不是 ECDSA。它解决了 nonce 问题，签名更小（固定 64 字节），验证更快。

本工具支持标准曲线上的 ECDSA。对新项目的一般签名需求，优先选 Ed25519。

## ECDSA 签名如何验证

验证检查 `s * G = (hash * r^-1) * 公钥 + (r * s^-1) * G`（粗略来说）。涉及两次标量乘法和一些模运算。关键性质：只有知道私钥的人才能为给定消息产生满足这个等式的 `s`。

## PS3、比特币和真实事故

ECDSA nonce 问题不是理论上的。2010 年，PS3 的 ECDSA 实现使用了静态 `k`。黑客提取了索尼的私钥，获得了将任意代码签名为"正宗索尼出品"的能力。2013 年，Android 的 `SecureRandom` bug 导致多个比特币钱包重用了 `k` 值；攻击者扫描区块链寻找具有重复 `r` 值的交易并清空了那些钱包。

教训：使用能安全处理 nonce 生成的库（确定性 RFC 6979 模式），或者更好的，直接用 Ed25519 从根本上避免这个问题。
