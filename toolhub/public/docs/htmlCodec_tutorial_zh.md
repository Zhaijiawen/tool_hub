# HTML 实体编解码 — 使用指南

在「原始字符」和「HTML 实体」之间互转。纯本地计算，不发网络请求。

## 什么时候用编码

**在网页上展示代码或标记**。直接把 `<div>` 写进 HTML 会被浏览器当成标签。先编码成 `&lt;div&gt;` 再放进页面，观众看到的就是字面文本。

**写技术文档、博客、教程**。所有示例代码里的 `<`、`>`、`&` 都要先过一遍编码，否则要么被浏览器吞掉，要么把后面的内容搅乱。

**处理含特殊字符的纯文本**。比如产品名「AT&T」——`&T` 开头的串在某些宽松解析器里会被误认为实体起始，编码成 `AT&amp;T` 最稳。

## 什么时候用解码

**从网页复制的内容是乱的**。复制来的文本显示成 `&quot;Hello&quot; &amp; Welcome`——粘进输入框、点解码，还原成 `"Hello" & Welcome`。

**清理模板和配置文件**。某些系统导出的模板把特殊字符存成了实体形式，解码后才是人能读的版本。

## 常见错误

**「无效的 HTML 格式」**：解码时输入里有孤立或不完整的实体（比如只有 `&lt` 没有分号，或者 `&foo;` 不是合法实体名）。检查输入，补齐分号。

**双重编码**：对已编码的文本再编码一次，会得到 `&amp;lt;` 这种双实体，显示出来是 `&lt;` 而不是 `<`。拿不准先解码一次看看。

**该转义的地方没转义**：本工具只处理你主动粘贴的内容。它不会扫描你的整个 HTML 文件——那应该是构建流程或编辑器插件的事。
