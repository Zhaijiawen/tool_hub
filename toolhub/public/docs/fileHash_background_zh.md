# 文件哈希校验 - 技术背景

哈希函数这东西，日常开发里到处都是，但很多人不太在意它是怎么工作的。Git 提交、软件包下载、密码存储，底层全是哈希。简单聊聊背后的原理。

哈希函数把任意长度的数据映射成固定长度的输出（摘要）。几个关键特性：

1. **确定性** -- 同样的输入永远得到同样的输出，没有随机因素。
2. **单向性** -- 从哈希值反推原始数据在计算上不可行。密码存储就靠这个。
3. **雪崩效应** -- 输入哪怕改一个 bit，输出面目全非。靠这个来检测数据有没有被篡改或者损坏。
4. **碰撞抵抗** -- 找到两个不同的输入产生相同的哈希值，应该极其困难。一旦有人能做到，这个算法就该退休了。

## 算法家谱

**MD5** 输出 128 位（32 个十六进制字符）。速度巨快，所以非安全场景校验和还是很多人用。但安全相关的东西千万别碰 MD5，碰撞攻击十几年前就演示过了。它适合"看看文件传输有没有损坏"，不适合任何需要防篡改的场景。

```
MD5("hello") = 5d41402abc4b2a76b9719d911017c592
```

**SHA-1** 输出 160 位（40 个十六进制字符）。2017 年 Google 的 SHAttered 攻击展示了实际碰撞，安全场景也该淘汰了。Git 还在用 SHA-1 做对象标识，不过他们折腾 SHA-256 迁移已经很久了。

```
SHA1("hello") = aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d
```

**SHA-256**（SHA-2 家族）是当前主力，256 位、64 个十六进制字符。下载页面上的校验值、比特币挖矿、数字签名，基本都靠它。目前来看还是安全的。

```
SHA256("hello") = 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

**SHA-512** 是 SHA-256 的大号版，512 位（128 个十六进制字符）。有点反直觉的是，在 64 位系统上 SHA-512 其实比 SHA-256 更快，因为它原生操作 64 位字。高安全场景和 TLS 证书常用。

## 实际用途

最常见的就是下载验证。下个 Linux ISO 或者 Node.js 安装包，官网一般会给出 SHA-256 值。把文件拖进哈希工具跑一下，跟官方值比对，就知道文件有没有损坏或者被人掉包。

文件去重也很实用。不用逐字节对比两个文件，算一下哈希就行。如果 SHA-256 一样，文件就是一样的（概率上来说基本不可能碰撞）。

密码存储不用多说了，永远别存明文。加盐哈希，登录时对用户输入做同样的哈希然后对比。就算数据库泄露了，攻击者也拿不到原始密码。

## 浏览器的 Web Crypto API

现代浏览器内置了 `SubtleCrypto`，可以直接在 JavaScript 里算 SHA 系列哈希，不用调后端：

```javascript
async function sha256(message) {
  const msgBuffer = new TextEncoder().encode(message)
  const hashBuffer = await crypto.subtle.digest('SHA-256', msgBuffer)
  const hashArray = Array.from(new Uint8Array(hashBuffer))
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('')
}
```

原生支持 `SHA-1`、`SHA-256`、`SHA-384`、`SHA-512`。没 MD5（这是好事），需要 MD5 的话用 `spark-md5` 之类的库。

性能方面，1GB 文件 SHA-256 大概 3-10 秒，看机器配置。大文件必须分片读，不然内存会爆。`File.arrayBuffer()` 或者 `FileReader.readAsArrayBuffer()` 配合流式处理就行。浏览器 SubtleCrypto 不原生支持增量哈希，所以超大文件可以考虑丢到 Web Worker 里跑，免得 UI 卡住。
