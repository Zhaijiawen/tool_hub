# Diff 文本对比 - 技术背景

## 什么是 Diff

Diff（Difference）算法是一种用于比较两个文本序列之间差异的算法。它广泛应用于版本控制系统（如 Git）、代码审查工具、文档管理系统等领域。

## 历史发展

Diff 算法最早由 Hunt 和 McIlroy 在 1975 年提出，随后被集成到 Unix 的 `diff` 命令工具中。至今，diff 已成为软件开发领域不可或缺的基础工具。

## 核心算法

### LCS（最长公共子序列）

大多数 diff 算法基于 LCS 算法。LCS 找出两个序列中最长的公共部分，从而推断出"哪些内容被添加"和"哪些内容被删除"。

### Myers Diff Algorithm

Eugene Myers 在 1986 年提出了一种更高效的 diff 算法，时间复杂度为 O(ND)，其中 N 是序列长度，D 是差异数量。该算法被 Git 等现代工具广泛采用。

## 对比粒度

### 行级对比（Line-level Diff）
- 以换行符为单位分割文本
- 适合代码文件、配置文件的对比
- 直观展示哪些行被修改、增加或删除

### 字符级对比（Character-level Diff）
- 精确到每个字符的变化
- 适合短文本的精确比对
- 可以看到单词或字母级别的改动

### 单词级对比（Word-level Diff）
- 以空白字符为分隔，逐词比较
- 适合自然语言文本（文章、文档）
- 能清晰展示用词变化

## 差异展示格式

### Unified Diff Format
Git 使用的标准格式，以 `+` 表示新增行，`-` 表示删除行，`@@` 标注变更位置。

### Side-by-side（并排对比）
左右两栏分别展示原始内容和修改内容，高亮显示差异部分，更直观易读。

### Inline Diff
在同一视图中用颜色标注增删，绿色背景为新增，红色背景为删除。

## 应用场景

### 代码审查
Pull Request 中的 diff 视图是代码审查的核心工具，帮助开发者快速了解改动内容。

### 文档版本追踪
论文、合同、技术文档的修订历史管理，确保每次改动都有据可查。

### 配置文件比对
运维场景中对比生产和测试环境的配置差异，避免因配置不一致导致的问题。

### 数据校验
对比 API 返回结果与预期值，用于自动化测试中的断言。

## 常用工具与库

| 工具/库 | 语言 | 特点 |
|---------|------|------|
| `diff` (npm) | JavaScript | 轻量，支持多种粒度 |
| `diff-match-patch` | 多语言 | Google 出品，功能强大 |
| `jsdiff` | JavaScript | 浏览器端友好 |
| GNU diff | C | Unix 标准工具 |
| vimdiff | Vim | 终端内对比工具 |

## 性能考量

对于超大文本（数万行），diff 计算可能较为耗时。可采用以下优化策略：
- 先过滤相同的前缀和后缀
- 使用 Web Worker 在后台线程计算
- 对超长文本分块处理
