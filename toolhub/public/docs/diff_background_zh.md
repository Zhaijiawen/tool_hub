# Diff 到底是怎么工作的

用 Git 的人每天都在跟 diff 打交道。`git diff` 告诉你改了啥，PR 页面展示 diff，合并冲突本质是两个 diff 撞上了。理解底层的原理能帮你更快更准地读懂和解决它们。

## 核心算法：最长公共子序列

大多数 diff 工具的核心思路是找两个文本之间的最长公共子序列（LCS）。找到了没变的部分，剩下的自然就是新增和删除。概念上很简单，但计算上有点意思 -- 两个各 1000 行的文件用朴素实现能算到天荒地老。

Git 和大多数现代 diff 工具实际用的是 **Myers diff 算法**（1986 年），时间复杂度 O(ND)，N 是总行数，D 是差异数。当两个文件很相似时（通常都是这样 -- 你在比较同一个东西的两个版本），D 很小，算法跑得很快。

## 三种对比粒度

### 行级对比
按换行切分，逐行比较。`git diff` 展示的就是这个。适合代码、配置文件和每行有独立意义的结构化文本。

### 字符级对比
精确到每个字符的变化。适合短文本或者需要看清单词内部改了什么。比如 "color" 变 "colour" -- 行级对比只告诉你"这行改了"，字符级能精确标出多了个 `u`。

### 单词级对比
以空白字符为界逐词比较。适合文章、文档、合同这类自然语言文本。展示的是"这个词改成了那个词"，而不是"整行都不一样了"。

## 三种展示格式

### Unified Diff
经典的 `+` 和 `-` 格式。`-` 开头的是删除的行，`+` 开头的是新增的行，既没有 `+` 也没有 `-` 的是上下文。`@@` 标记标明对比的行号范围。

### 并排对比（Side-by-side）
左右两栏，旧版在左新版在右。差异在两栏同时高亮。大多数代码审查工具用这种格式，读起来最直观。

### 内联对比（Inline）
单栏视图，新增用绿色背景，删除用红色背景。比并排紧凑，但复杂改动可读性不如并排。

## Diff 的实际应用场景

- **代码审查**：每个 PR 的 review 本质上就是读 diff。快速准确地读 diff 是基本功。
- **配置管理**：上线前对比生产环境和测试环境的配置差异，防止配置漂移导致事故。
- **文档版本追踪**：需求文档、合同、规范的改动记录。
- **排查问题**："正常版本和挂了版本之间改了什么？"diff 一下两个状态就知道了。

## 性能说明

超大文件（几万行）的 diff 计算确实会慢。这个工具用的是 JavaScript 实现，对于典型使用场景（几千行以内）完全够用。对于海量对比，预过滤相同的前后缀、用 Web Worker 后台计算等策略可以加速，但实际中大多数场景用不到这些优化。
