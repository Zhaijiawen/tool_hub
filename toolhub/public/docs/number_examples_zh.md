# 数字转换器 - 使用示例

## 标准转换表

### 十进制 255 -- 经典值

一个字节全位为 1。到处出现：颜色通道、IP 段、二进制掩码。

| 进制 | 值 |
|---|---|
| 十进制 | `255` |
| 二进制 | `11111111` |
| 八进制 | `377` |
| 十六进制 | `FF` |

### 十六进制 1A3F

| 进制 | 值 |
|---|---|
| 十六进制 | `1A3F` |
| 十进制 | `6719` |
| 二进制 | `1101000111111` |
| 八进制 | `15077` |

### 二进制 10101010 -- 交替模式

| 进制 | 值 |
|---|---|
| 二进制 | `10101010` |
| 十进制 | `170` |
| 八进制 | `252` |
| 十六进制 | `AA` |

输出 `AA` 很漂亮 -- 二进制交替的位变成十六进制重复的 A。两个十六进制字符对应一个字节，这就是为什么十六进制读取二进制数据这么方便。

## 实际场景

### 颜色代码

`#FF6600` 拆解：
- 红色：`FF` = 255（全亮）
- 绿色：`66` = 102（约 40% 亮度）
- 蓝色：`00` = 0（关闭）

常见缩写 `#F60` 是一样的：`F` = `FF`，`6` = `66`，`0` = `00`。理解了十六进制和十进制的转换，CSS 颜色就不神秘了。

### Unix 权限

`chmod 755` 的含义：

| 八进制位 | 二进制 | 权限 |
|---|---|---|
| 7 | `111` | rwx（读、写、执行） |
| 5 | `101` | r-x（读、不能写、执行） |
| 5 | `101` | r-x（读、不能写、执行） |

所以 755 = 文件所有者可以一切操作，组和其他用户只能读和执行但不能写。`chmod 644`（rw-r--r--）是另一个常见值 -- 6 二进制是 `110`（rw-），4 是 `100`（r--）。

### 内存地址

`0x7FFE5B4C2A30` 是 64 位系统上的典型栈地址。`0x` 前缀是 C/JavaScript/Go 的十六进制字面量标准记法。`0b` 表示二进制，`0o` 表示八进制（现代 JS）。单独的 `0` 前缀（如 `0777`）在 C 里是八进制但在 JS 严格模式下不合法 -- 别用。

### 位掩码

- `0xFF` = 保留低 8 位
- `0xFFFF` = 保留低 16 位
- `0xFFFFFFFF` = 保留低 32 位

十进制下：`0xFF` = 255，`0xFFFF` = 65535，`0xFFFFFFFF` = 4294967295。系统编程中需要掩码、位移、提取位的时候这些数字天天见。

### 浮点数坑

```javascript
0.1 + 0.2 === 0.3 // false -- 实际是 0.30000000000000004
```

不是 JavaScript 抽风。这是 IEEE 754 双精度的天生问题。0.1 在二进制中是循环小数（就像 1/3 在十进制中），没法精确存储。标准解决：带容差比较：

```javascript
Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON // true
```
