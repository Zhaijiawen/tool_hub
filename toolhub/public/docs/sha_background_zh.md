# SHA 哈希家族技术背景

SHA（安全哈希算法）是 NIST 标准化的密码学哈希函数家族。你每天都在用 SHA -- Git 提交哈希、TLS 证书、区块链工作量证明、软件校验和。哈希函数接受任意输入，产生固定大小的输出（"摘要"），具有几个关键特性：确定性（相同输入总是相同输出）、单向性（无法从哈希恢复输入）、抗碰撞性（很难找到两个不同输入有相同哈希）、以及雪崩效应（即使输入微小变化输出也剧烈改变）。

## SHA 家族谱系

**SHA-1**（160 位摘要，1995）：曾是二十年的标准。现在已被破解。研究者在 2017 年展示了实用的碰撞攻击（SHAttered）。Git 提交哈希仍使用 SHA-1，不过正在向 SHA-256 迁移。新项目不要用 SHA-1。

**SHA-2 家族**（2001）：当前的主力。有四种大小：
- SHA-224：224 位。很少使用。
- SHA-256：256 位。最常用。用于 TLS、比特币、PGP。
- SHA-384：384 位。更高安全性。
- SHA-512：512 位。也很常见，尤其在 64 位平台上比 SHA-256 更快。

SHA-256 对碰撞攻击提供 128 位安全性，对前像攻击提供 256 位。对所有当前应用都足够。

**SHA-3**（2015）：不是 SHA-2 的替代品，而是一种内部分设计完全不同的替代方案（Keccak 海绵结构）。目前 SHA-2 仍是默认选择。SHA-3 在那等着，万一 SHA-2 将来出现问题。

## 长度扩展攻击

SHA-256（和 SHA-512）容易受到长度扩展攻击：给定 H(消息) 和消息长度，你可以在不知道原始消息的情况下计算 H(消息 || 后缀)。这对 H(密钥 || 消息) 这类朴素的 MAC 构造是个问题。如果你在构建 MAC，用 HMAC（免疫长扩攻击）或 SHA-3（设计上就不存在这个漏洞）。不要自己搞"密钥前缀哈希"认证。

## SHA 用于密码？不行。

SHA 很快。这是它的设计目标。但对密码哈希来说，快是坏处 -- 你希望哈希慢且内存密集，这样攻击者无法大规模暴力破解。密码用 bcrypt、Argon2 或 scrypt。绝不要用 SHA-256 或 SHA-512 存储密码，除非你在 PBKDF2 中用很高的迭代次数和恰当的盐值。

## 实际用途

- **完整性验证**：哈希文件并与公布的哈希对比，验证文件未被修改。
- **提交/交易标识符**：Git 和区块链用 SHA 哈希作为内容寻址标识。
- **数字签名**：签名消息的 SHA 哈希而非消息本身。
- **密钥派生**：作为 HKDF 或 PBKDF2 的一部分。
- **工作量证明**：比特币使用双重 SHA-256。

## 该选哪个 SHA？

几乎所有场景用 SHA-256。64 位系统需要更高吞吐量时用 SHA-512（SHA-512 处理 64 位字，在 64 位 CPU 上可能比 SHA-256 更快）。想要结构上不同的替代方案时用 SHA-3。完全避免 SHA-1。
