# HTTP 状态码 -- 技术背景

每个 HTTP 响应都带一个 3 位数状态码，服务端用这个数字告诉你"请求怎么样了"。理解状态码不是后端专属的事 -- 前端对接 API 的时候，不知道这些数字的含义就只能瞎猜。

## 五大类

第一位数字决定类别。记住这个比记住具体每个码有用得多，因为你可以根据首位数字推断大致情况。

| 范围 | 类别 | 意思 |
|---|---|---|
| 1xx | 信息性 | "收到请求了，还在处理。"实际上很少见到。 |
| 2xx | 成功 | "一切正常。"理想路径。 |
| 3xx | 重定向 | "你要的资源搬家了，去别处找吧。" |
| 4xx | 客户端错误 | "你这边出了问题。"请求不对、没认证、资源不存在。 |
| 5xx | 服务端错误 | "我这边出了问题。"服务器崩了。 |

## 实际会遇到的

### 2xx -- 成功

`200 OK` 是默认响应，每天看到成千上万次。`201 Created` 应该从创建资源的 POST 接口返回 -- 告诉客户端"我建好了，在这里找"（通过 `Location` 头）。`204 No Content` 给那些操作成功但没啥要返回的，比如 DELETE。

### 3xx -- 重定向

`301 Moved Permanently` 告诉搜索引擎更新索引。`302 Found` 是临时搬家 -- 浏览器会跟随但搜索引擎保留旧 URL。`304 Not Modified` 是缓存的幕后功臣：客户端带上 `If-None-Match` 和 ETag，如果资源没变，服务端就回一句"用你已有的就行"，零 body，省带宽、快。

### 4xx -- 客户端错误

`400 Bad Request` 是输入有问题的通用兜底。`401 Unauthorized` 是"你是谁？"-- 没发凭证或者凭证过期了。`403 Forbidden` 是"我知道你是谁，但你还是不能看。"`404 Not Found`，这个不用解释。`405 Method Not Allowed` 常见于把 POST 请求发到了只支持 GET 的接口。`429 Too Many Requests` 是限流触发了。

### 5xx -- 服务端错误

`500 Internal Server Error` 是"出错了但不知道为什么"的通用兜底。`502 Bad Gateway` 说明你的反向代理（nginx、负载均衡）从上游拿到了垃圾响应。`503 Service Unavailable` 是"等一下再试" -- 通常发生在部署或过载时。`504 Gateway Timeout` 是上游响应太慢了。

## API 设计约定

一个设计良好的 REST API，状态码应该讲一个一致的故事：

- `POST /users` 创建用户，返回 `201 Created`，带 `Location: /users/42` 头
- `DELETE /users/42`，返回 `204 No Content`（或者 `200` 带上被删的资源）
- 认证 token 不对？`401`。token 对但权限不够？`403`。
- 输入校验失败？`422 Unprocessable Entity` 比 `400` 更准确，虽然很多人直接用 `400`

一个关键原则：别返回 `200 OK` 然后在 body 里塞错误信息。这破坏了 HTTP 语义，客户端没法统一处理错误。出问题了就用 4xx 或 5xx。
