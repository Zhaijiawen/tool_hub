# 数字转换器 -- 技术背景

不同进制只是同一个值的不同写法。计算机用二进制思考，人类习惯十进制，而程序员花大量时间泡在十六进制里。这个工具在不同进制之间即时翻译。

## 四种常用进制

### 十进制（base 10）
数字 0-9。从小用到大的那套。不特别说明时默认就是这个。`255`、`4096`、`-42`。

### 二进制（base 2）
只有 0 和 1。计算机底层就是用这个存所有东西 -- 晶体管只有开和关两个状态。`11111111` 是 255。每位叫一个 **bit**；8 个 bit 组成 1 个 **字节**。二进制写长了极其难读 -- 一个 32 位整数是 32 个 0 或 1。

### 八进制（base 8）
数字 0-7。现在用得少了，但 Unix 文件权限还在用（`chmod 755`），每位代表三个 bit 的读写执行权限。一些遗留系统和航空应答机编码也在用。

### 十六进制（base 16）
数字 0-9 加 A-F（或 a-f）。编程的主力进制。两个十六进制字符精确表示一个字节，所以 `FF` = 255，`00` = 0，`7F` = 127。十六进制到处都是：颜色代码（`#FF6600`）、内存地址（`0x7FFE5B4C2A30`）、二进制 dump、MAC 地址、Unicode 码点、哈希摘要。

## 转换原理

核心是位权记数法。每位数字的值 = 数字 x 进制的位次幂（从右往左数，从 0 开始）：

```
二进制 1011 -> 1 x 2^3 + 0 x 2^2 + 1 x 2^1 + 1 x 2^0 = 8 + 0 + 2 + 1 = 11
十六进制 FF -> 15 x 16^1 + 15 x 16^0 = 240 + 15 = 255
八进制 377 -> 3 x 8^2 + 7 x 8^1 + 7 x 8^0 = 192 + 56 + 7 = 255
```

反过来（十进制转其他进制）用重复除法：不断除以目标进制，记录余数，商变成零后把余数倒过来读。

## 有符号整数和补码

计算机用补码表示负数。对于 n 位有符号整数：

- 范围：-2^(n-1) 到 2^(n-1) - 1
- 8 位有符号：-128 到 127
- 32 位有符号：约 -21 亿到 +21 亿

取负数的方法：所有位取反，然后加 1。所以 `00000001`（1）变成 `11111110 + 1 = 11111111`（-1）。这就是为什么 `11111111` 可以表示 255（无符号）或 -1（有符号）-- 位模式一样，解读不同。

## 浮点数和为什么 0.1 + 0.2 != 0.3

IEEE 754 浮点数用符号位、指数和尾数（小数部分）表示实数，类似二进制的科学计数法。问题在于很多简单的十进制小数（如 0.1）在二进制中是循环小数，无法精确存储。结果就是微小的舍入误差不断累积：

```javascript
0.1 + 0.2 // 0.30000000000000004
```

这不是 bug -- 是二进制浮点表示的天生缺陷。需要精确十进制运算的话，用整数分或者专门的十进制库。
