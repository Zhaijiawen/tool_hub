# URL 解析器 — 使用教程

URL 解析器有三个 Tab，各自服务于不同目的。搞清楚流程之后用起来飞快。

## 解析 URL

把完整 URL 粘贴到输入框。解析自动触发——不用点按钮。顶部有个标签告诉你 URL 是合法还是非法，这算是深入细节前的一次快速合理性检查。

「结构解析」Tab 显示每个字段的拆分结果：protocol、hostname、port、pathname、search、hash、origin——完整拆解。每个字段旁边都有复制按钮，你可以只拿 hostname 或只拿 path，不用手动选中文本。

有一个容易踩的坑：解析器需要协议前缀。输入 `example.com/path` 没用——必须是 `https://example.com/path`。没有协议的话，浏览器的 URL 构造函数解析不了。加个 `https://` 就行。

## 查看查询参数

切到「Query 参数」Tab，你会看到每个参数以键/值表格形式展示。这比在地址栏里眯眼看一长串查询字符串清楚太多了。

勾选「URL 解码显示」把百分号编码的文本转回可读形式。`%E4%B8%AD%E6%96%87` 变成它代表的实际汉字。如果你需要原始编码值来发请求，就不勾选。

每行参数有自己的复制按钮，用于单独复制某个值。底部的「复制全部参数」按钮把整组参数以 `key=value&key=value` 格式复制，这就是你要粘贴到 curl 命令或 API 客户端里的格式。

## 反向构建 URL

「反向构建」Tab 是反方向工作的。解析一个 URL 后，所有字段都预先填好了。改动任意字段——换 hostname、加端口、追一段路径——底部的「构建结果」实时更新。

构造 API URL 的时候这超级有用。解析一个请求拿到基础结构，然后递进式修改。要从 `page=1` 切到 `page=2`？改参数值，不用编辑原始 URL 字符串。要从 staging 切到 production？改 hostname，其他一切不变。

## 当结果看起来不对时

- **URL 显示非法但浏览器里能用**：大概率忘了协议。加上 `https://`。
- **参数值显示乱码**：打开 URL 解码。原始查询字符串是百分号编码的。
- **hash 里面的查询参数没显示**：它们在 `hash` 字段里，不是 `search`。解析器正确分开了它们——检查 hash 值，如果需要其内部结构就单独解析那个字符串。
- **端口是空的但你预期有端口**：如果 URL 用的是协议的默认端口（HTTP 80、HTTPS 443），解析器会省略它。这是标准浏览器行为——端口是隐式的。
