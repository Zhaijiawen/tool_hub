# 空白字符处理 — 技术背景

空白字符是看不见的，正因如此它才制造了那么多的问题。人眼看着一模一样的两个字符串，对计算机来说可能因为一个尾随空格、一个应该用空格却用了制表符的位置，或者一个伪装成普通空格的非断行空格，而完全不同。

空白字符处理工具解决两种最常用的清理操作：trim（去除首尾空白）和 compress（把连续多个空白压缩成单个）。

## 什么算空白字符

显然的有空格（` `）、制表符（`\t`）、换行符（`\n`）和回车符（`\r`）。但 Unicode 定义了很多其他的空白字符：

| 字符 | 码点 | 名称 | 在什么地方会碰到 |
|---|---|---|---|
| 空格 | U+0020 | SPACE | 无处不在 |
| 制表符 | U+0009 | CHARACTER TABULATION | 代码缩进、TSV 文件 |
| 换行符 | U+000A | LINE FEED | Unix/Mac 行尾 |
| 回车符 | U+000D | CARRIAGE RETURN | Windows 行尾（`\r\n`） |
| 不间断空格 | U+00A0 | NO-BREAK SPACE | 复制的网页内容、Word 文档 |
| 零宽空格 | U+200B | ZERO WIDTH SPACE | 富文本编辑器输出、部分 emoji 序列 |

不间断空格（U+00A0）特别狡猾。它看起来跟普通空格一模一样，但所在位置不允许断行。它经常出现在从网页、Word 文档、HTML 邮件复制来的文本里。JavaScript 的 `.trim()` 不会去掉它——只有正则里的 `\s` 能匹配。工具会处理它。

零宽空格更糟：完全看不见，宽度为零。你可以在看似一个完整单词的中间藏一个，直到字符串比较神秘地失败你才发现。

## 为什么空白字符很重要

- **字符串比较**：`"hello" === "hello "` 结果是 `false`。差别不可见。
- **数据库查询**：`WHERE name = 'John'` 匹配不到存储值是 `'John '` 的那行。
- **哈希/摘要不匹配**：一个尾随换行能把文件的 MD5/SHA 彻底改变。两个看起来一样的配置文件可能有不同的哈希值。
- **CSV 解析**：逗号后面多一个空格就能破坏字段匹配——`"New York"` vs `" New York"`。
- **表单验证**：用户在输入或复制粘贴时经常无意间加上空格。

## Trim vs. compress

Trim 只去掉文本开头和结尾的空白字符。内部的空白（词之间的空格）保持不变。这是清理表单输入时该用的——`"  张三  "` 变成 `"张三"`。

Compress 更进一步：把每一个由一个或多个空白字符组成的序列替换为单个空格，同时去掉首尾空白。`"hello    world   foo"` 变成 `"hello world foo"`。这是规范化间隔不规则的文本时该用的——粘贴的内容、日志条目、任何混用了制表符和空格的东西。

底层实现上，compress 用的是类似 `\s+` 的正则来匹配任意空白序列并替换为单个空格。工具还会处理 `.trim()` 遗漏掉的那些 Unicode 空白字符。
