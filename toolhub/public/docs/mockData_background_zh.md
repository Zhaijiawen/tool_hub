# Mock 数据生成 — 为什么需要假数据

Mock 数据就是看起来像真的假数据。结构和真实数据一样，但内容是随机生成的——没有真实个人信息、没有真实邮箱、什么都没有真的。在真实数据还不存在、或者用真实数据会出问题的时候用。

## 三个核心场景

**前端没法等后端 —** 接口还没写好，但页面今天就得开工。Mock 数据让你用看起来合理的数据把组件先搭起来，后面换成真实接口时组件代码不用改。

**测试需要多样性 —** 单元测试里写死三条数据查不出什么问题。生成器能自动造边界情况：空字符串、超长名字、边界数值、各种状态组合。还能一次生成一千条看列表渲染性能扛不扛得住。

**演示要安全 —** 产品演示、UI 评审时展示真实用户数据有隐私风险。Mock 数据看着真实但不涉及任何敏感信息。

## 各种方案的对比

| 方案 | 工具 | 适合 |
|------|------|------|
| 代码库 | Faker.js、@faker-js/faker | 测试里程序化生成、写种子脚本 |
| 可视工具 | 这个工具、Mockaroo | 快速生成一次性数据集，不用写代码 |
| Mock 服务器 | JSON Server、MSW | 搭建一个能响应真实 HTTP 请求的假 API |
| 接口平台 | Apifox、RAP2 | 团队级 API Mock，带协作功能 |

## 输出格式

工具生成标准 JSON 数组：

```json
[
  {
    "id": 4512,
    "name": "张三",
    "email": "zhangsan@example.com",
    "status": "active",
    "tags": ["vue", "node"]
  }
]
```

这个格式可以直接被 `JSON.parse()` 解析、用 MongoDB 的 `insertMany` 批量导入、或者作为 Mock 服务器的静态数据文件。

## 好的 Mock 数据长什么样

设计 Mock schema 时要覆盖常见的字段类型：

| 类别 | 示例字段 |
|------|---------|
| 标识符 | id、uuid |
| 个人信息 | 姓名、邮箱、手机号 |
| 时间 | createdAt、updatedAt |
| 状态枚举 | status: active/inactive/pending |
| 数值范围 | price、age、quantity |
| 嵌套结构 | address 对象、tags 数组 |
