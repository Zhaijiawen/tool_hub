# ECDH 技术背景

ECDH（椭圆曲线 Diffie-Hellman）是经典 Diffie-Hellman 密钥交换的椭圆曲线版本。传统 DH 在模大素数的群中运算，ECDH 在椭圆曲线上运算。结果是一样的能力 -- 两方在公开信道上协商共享密钥 -- 但密钥小得多。256 位 ECDH 密钥的安全性大致等同于 3,072 位传统 DH 密钥。

## 工作原理

Alice 生成私钥（随机数），用曲线生成元乘以它得到公钥：`A = a * G`。Bob 也一样：`B = b * G`。他们交换公钥。Alice 计算 `a * B = a * b * G`，Bob 计算 `b * A = b * a * G`。两人到达曲线上的同一点 -- 这就是共享密钥。

窃听者看到 `A` 和 `B`，但不知道 `a` 或 `b` 就无法计算 `a * b * G`。这就是椭圆曲线离散对数问题（ECDLP），被认为在经典计算机上不可行。

## 曲线选择极其重要

不是所有曲线都一样安全。今天 ECDH 的安全选择是：

- **Curve25519**（Bernstein，RFC 7748）：专为 ECDH 设计。快、恒定时间、故意设计得难以实现出错。WireGuard、Signal 和现代 TLS 都在用。曲线参数完全透明（p = 2^255 - 19）。

- **NIST P-256**（secp256r1）：传统选择，仍然广泛使用且被认为安全。Dual_EC_DRBG 后门丑闻后有些人不信任 NIST 曲线，但 P-256 经过独立分析。

对新项目，明确推荐 Curve25519。它消除了 P-256 实现可能遇到的整类错误（无效曲线攻击、小子群攻击、时序泄露）。

## 从共享密钥到加密密钥

裸 ECDH 共享密钥是椭圆曲线点，不是字节串。通常取共享点的 x 坐标，然后通过密钥派生函数（KDF）如 HKDF 来产生适合 AES 或 ChaCha20 的对称密钥。不要直接把原始 x 坐标当密钥用 -- KDF 存在是有原因的，跳过这一步是常见的密码实现错误。

## 前向安全性

ECDH 在使用临时密钥时提供前向安全性 -- 每个会话生成新密钥对，用完丢弃。即使你的长期密钥后来被泄露，过去的会话密钥也无法恢复，因为临时私钥已经不在了。这就是为什么 TLS 1.3 强制要求临时密钥交换并完全取消了静态 RSA 密钥交换。

## ECDH vs X25519

X25519 是建立在 Curve25519 上的特定 ECDH 函数。它是"做对了"的 ECDH -- 极简 API：私钥（32 字节）、公钥（32 字节）、返回共享密钥（32 字节）。不用配置曲线参数，不会漏掉点验证。如果你今天在实现密钥交换，直接用 X25519。本站的"ECDH"工具使用 NIST 曲线上的标准 ECDH；单独的 X25519 工具处理现代变体。
