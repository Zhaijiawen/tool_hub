# ECDH 技术背景

## 概述
椭圆曲线迪菲-赫尔曼（ECDH）是一种密钥协商协议，允许两方在不安全信道上建立共享密钥。ECDH基于椭圆曲线的数学特性，提供前向安全性，使其能够抵抗未来的密钥泄露。它广泛应用于现代密码协议中，包括TLS、SSH和安全消息应用。

## 数学基础

### 椭圆曲线
ECDH在有限域上定义的椭圆曲线上运行。最常用的曲线包括：
- NIST P-256 (secp256r1): 256位曲线，广泛用于TLS
- Curve25519: 255位曲线，专为高性能设计
- NIST P-384 (secp384r1): 384位曲线，提供更高安全性
- Brainpool曲线: 具有不同安全特性的替代曲线

### 点运算
ECDH的安全性依赖于椭圆曲线离散对数问题（ECDLP）的困难性：
- 点加法: 给定两个点P和Q，计算P + Q
- 标量乘法: 给定点P和标量k，计算kP
- ECDLP: 给定点P和Q = kP，找到标量k

### 密钥交换过程
1. 双方生成各自的私钥（随机标量）
2. 每方通过标量乘法计算公钥
3. 双方在不安全信道上交换公钥
4. 每方使用自己的私钥和对方的公钥计算共享密钥
5. 双方得到的共享密钥相同

## 核心算法结构

### 密钥生成
```python
# 生成私钥（随机标量）
private_key = random_scalar()

# 计算公钥
public_key = private_key * G  # G是生成点
```

### 共享密钥计算
```python
# 方A计算共享密钥
shared_secret_A = private_key_A * public_key_B

# 方B计算共享密钥  
shared_secret_B = private_key_B * public_key_A

# shared_secret_A == shared_secret_B
```

## 安全性分析

### 密码学强度
- ECDH安全性取决于ECDLP的困难性
- 密钥大小比RSA小得多，但提供同等安全性
- 256位ECDH提供约128位安全级别
- 前向安全性：长期密钥泄露不影响过去的会话

### 攻击方法
- 对ECDLP的暴力攻击
- 侧信道攻击（时序、功耗分析）
- 实现漏洞
- 曲线特定攻击（如果使用弱曲线）

### 安全考虑
- 曲线选择对安全性至关重要
- 私钥的正确随机数生成
- 接收公钥的验证
- 防止小子群攻击

## 实现考虑

### 曲线标准
- NIST曲线: 广泛标准化，政府批准
- Curve25519: 高性能，恒定时间操作
- Brainpool曲线: NIST曲线的替代方案
- 自定义曲线: 需要仔细的安全分析

### 性能特征
- 比RSA密钥交换快得多
- 更小的密钥大小减少带宽
- 对资源受限设备高效
- 现代处理器提供硬件加速

## 标准和合规

### NIST指南
- SP 800-56A: 使用有限域密码学的密钥协商
- SP 800-56B: 使用整数分解密码学的密钥协商
- FIPS 186-4: 数字签名标准

### RFC标准
- RFC 4492: TLS的ECC密码套件
- RFC 5656: SSH的椭圆曲线算法
- RFC 7748: 安全椭圆曲线

## 应用和用例

### 传输层安全
- TLS 1.3使用ECDH进行密钥交换
- 完美前向安全性
- 减少计算开销
- 更小的证书大小

### 安全外壳（SSH）
- SSH 2.0中的ECDH密钥交换
- 比RSA密钥交换更快
- 更好的安全特性

### 安全消息
- Signal协议使用ECDH
- 端到端加密
- 完美前向安全性
- 可否认认证

### 物联网和嵌入式系统
- 低计算要求
- 小内存占用
- 电池友好操作
- 硬件加速支持
