# 正则表达式测试器 — 技术背景

但凡在终端或编辑器里混过的，多少都见过正则表达式——那种用斜杠包起来的咒语，看起来乱七八糟但偏偏能精准命中你要的东西。正则本质上就是一个用字符描述出来的搜索模式，JavaScript、Python、Go、Java、Shell 全都在用。表单校验、日志解析、批量替换，正则就是那把一直揣在兜里的瑞士军刀。

## 基本构件

大多数时候字符直接匹配自身，`abc` 就是字符串 "abc"，没啥花活。真正的威力来自元字符——那些改变了匹配规则的特殊符号。

| 符号 | 做了什么 |
|---|---|
| `.` | 匹配任意单个字符（换行符除外） |
| `^` | 锚定字符串开头（加了 `m` 标志就是行首） |
| `$` | 锚定字符串结尾（加了 `m` 标志就是行尾） |
| `*` | 前面的东西出现零次或多次 |
| `+` | 前面的东西出现一次或多次 |
| `?` | 前面的东西可有可无。放在量词后面会切换为懒惰模式 |
| `\` | 转义：让下一个元字符变回普通字符 |
| `|` | 分支选择——左右两边匹配任一即可 |
| `()` | 捕获分组，同时还控制运算优先级 |
| `[]` | 字符类——匹配方括号里的任意一个字符 |
| `{}` | 精确数量控制 |

## 字符类

与其把所有可能字符一一列出来，不如用这些简写。紧凑而且更易读。

| 模式 | 匹配内容 |
|---|---|
| `[abc]` | a、b 或 c 中的一个 |
| `[^abc]` | 除了 a、b、c 之外的任何字符 |
| `[a-z]` | 所有小写字母 |
| `[0-9]` | 所有数字 |
| `\d` | 数字，等价于 `[0-9]` |
| `\D` | 非数字 |
| `\w` | 单词字符：`[a-zA-Z0-9_]` |
| `\W` | 非单词字符 |
| `\s` | 空白字符（空格、制表符、换行符） |
| `\S` | 非空白字符 |

## 量词

你不会只想要一个字符，量词告诉引擎前面的东西要拿几个。

| 模式 | 含义 |
|---|---|
| `a{3}` | 恰好三个 a |
| `a{2,4}` | 两到四个 a |
| `a{2,}` | 至少两个 a，上不封顶 |

这里有个常见的坑：量词默认是贪婪的——能拿多少拿多少。在量词后面加个 `?`（比如 `*?` 或 `+?`）它就变懒惰了，能少拿就少拿。如果你用 `.*` 去解析 HTML，一不小心就会把整个文档吞进去，所以什么时候用懒惰模式得心里有数。

## 标志

标志调整整个模式的匹配行为，跟模式本身分开设置。

| 标志 | 作用 |
|---|---|
| `g` | 全局匹配——返回所有结果，不光是第一个 |
| `i` | 忽略大小写——`[a-z]` 同时匹配 `[A-Z]` |
| `m` | 多行模式——`^` 和 `$` 锚定到行首行尾而非整个字符串 |
| `s` | dotall——让 `.` 也能匹配换行符 |

实践中你几乎总是组合使用。`/[a-z]+/gi` 捕获每一段连续的字母，不区分大小写——这属于常规操作。真正有意思的是什么时候开 `m` 来处理逐行日志，什么时候开 `s` 来把多行内容当成一整块匹配。

## 分组和环视

捕获组 `(pattern)` 用来从匹配结果中提取子串。第一对括号的内容存到 `$1`，第二对存到 `$2`，以此类推。做查找替换的时候，`$1` 让你在不丢数据的前提下重排文本——比如把 "张三, 李四" 变成 "李四 张三"，用 `(\w+),\s(\w+)` 和 `$2 $1` 一步到位。

非捕获组 `(?:pattern)` 的行为跟普通分组一样（控制优先级），但不产生反向引用。需要分组控制但不在乎捕获内容时用它。

环视是零宽断言——检查某样东西存在或不存在但不消耗字符：
- `(?=pattern)` — 正向先行断言：后面必须跟着这个
- `(?!pattern)` — 负向先行断言：后面绝对不能有

经典用法：`\d+(?=px)` 只在数字紧跟着 "px" 时才匹配，所以 `12px` 返回 `12`，而 `12em` 不理你。从 CSS 里抠数值、从 style 属性里提取尺寸、解析任何上下文决定含义的格式——这种场景都靠它。
