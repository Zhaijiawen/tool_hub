# 空白字符处理 — 使用教程

空白字符工具有两种模式，各干一件事。选你需要的那个就行。

把文本粘贴到输入区。多行文本完全支持——两种模式都能处理。

**去除首尾空白（Trim）**去掉文本开头和结尾的空白字符。中间的所有内容原封不动。这是清理表单输入的操作：用户打字或粘贴时不小心带了前导或尾随空格，trim 在数据进入校验或数据库之前将它规范化。

**压缩空白（Compress）**更激进。把每一串空白字符——多个空格、混用的制表符和空格、空白行间隙——替换为单个空格。同时去掉首尾空白。结果是每个词之间恰好一个空格，两端没有空白。

点操作按钮，处理后的文本显示在输出区。点**复制**拿走。

## 什么时候用哪个

Trim 是清理单个值的默认选择。如果你在处理名字字段、邮箱地址或搜索查询，trim 就够了。`"张三"` 内部的空格应该保留——只去掉边缘的空白给你一个干净的值。

Compress 用于那些间隔已经乱掉的文本块。想想从 PDF 粘贴的内容，词之间随机出现大间隙；或者某人在逗号周围用了不均匀空格的 CSV 文件；或者制表符和空格混用不一致的代码。Compress 把一切规范化为干净的单空格。

一种不那么常见但有用的混合方式：先 trim，再决定是否还需要 compress。有时候只是首尾有问题。

## 空白字符在哪些地方让你头疼

- **登录表单**：用户名或密码字段尾随的空格导致凭据不匹配。后端哈希的是 `"password"`，用户发的是 `"password "`——不同的哈希值，登录失败，用户一脸懵。哈希之前先 trim。
- **CSV 导入**：`"纽约"` 和 `" 纽约"` 是不同的值。你的数据库多了一个拼写稍有差异的重复城市。预处理阶段给每个字段 compress 或 trim。
- **Diff 工具**：两个尾随空白不同的文件如果 diff 算法对空白敏感，会显示成整篇都被修改。比较前先 trim。
- **API 集成**：合作方的 API 可能返回间隔不一致的字符串。处理前先 compress 规范化你的输入，不管对方发了什么来。
