# 图片压缩 - 技术背景

## 为什么需要图片压缩

图片通常是网页中最大的资源之一。据统计，图片平均占网页总体积的 50% 以上。优化图片可以：
- 加快页面加载速度（用户体验）
- 减少流量消耗（移动端尤为重要）
- 降低服务器带宽成本
- 提升 SEO 评分（Google 将页面速度纳入排名因素）

## 图片格式对比

### JPEG（JPG）
- **特点**：有损压缩，支持照片级色彩深度
- **适用**：照片、复杂色彩图像
- **不适用**：文字、图标、透明背景图
- **压缩原理**：离散余弦变换（DCT），通过降低高频信息精度来减小文件体积

### PNG
- **特点**：无损压缩，支持透明通道（Alpha 通道）
- **适用**：图标、截图、需要透明背景的图
- **不适用**：大型照片（文件体积大）
- **压缩原理**：DEFLATE 压缩算法，无损但体积较大

### WebP
- **特点**：Google 开发，支持有损和无损压缩，支持透明度和动画
- **适用**：大多数 Web 场景（可替代 JPEG 和 PNG）
- **体积优势**：比 JPEG 小 25-35%，比 PNG 小 26%
- **浏览器支持**：Chrome、Firefox、Safari（14+）、Edge 均支持

### AVIF
- **特点**：新一代格式，基于 AV1 视频编码
- **体积优势**：比 WebP 更小，比 JPEG 小 50%
- **兼容性**：较新，部分旧浏览器不支持

## 压缩算法原理

### 有损压缩（Lossy）
通过丢弃人眼不敏感的细节信息来减小文件体积：
1. 色彩量化：减少颜色数量
2. 降低色度分辨率（色彩丰富度比亮度对人眼影响更小）
3. 频率域压缩：DCT + 量化，降低高频细节精度

### 无损压缩（Lossless）
通过统计规律和编码方式减小文件体积，不丢失任何信息：
1. 预测编码：根据相邻像素预测当前像素值
2. 熵编码：用更短的编码表示频繁出现的模式（Huffman 编码）
3. LZ77 等字典压缩算法

## browser-image-compression 库

本工具使用 `browser-image-compression` 库在浏览器端进行图片压缩：

- **纯前端**：完全在浏览器中运行，不需要服务器
- **WebWorker**：在后台线程压缩，不阻塞 UI
- **支持格式**：JPEG、PNG、WebP
- **功能**：调整质量、限制最大尺寸、限制最大文件大小

```javascript
import imageCompression from 'browser-image-compression'

const options = {
  maxSizeMB: 1,           // 最大 1MB
  maxWidthOrHeight: 1920,  // 最大边长 1920px
  useWebWorker: true,      // 使用 WebWorker
  fileType: 'image/jpeg',  // 输出格式
  initialQuality: 0.8      // 初始质量 80%
}

const compressedFile = await imageCompression(originalFile, options)
```

## 压缩质量选择建议

| 质量 | 适用场景 | 体积节省 |
|------|---------|---------|
| 90%+ | 重要照片、商业用途 | 约 20-30% |
| 75-90% | 网站展示图、博客 | 约 40-60% |
| 60-75% | 缩略图、预览图 | 约 60-70% |
| 40-60% | 仅参考用的极小图 | 约 70-80% |

注：PNG 格式的有损压缩效果不如 JPEG，因为 PNG 本身是无损格式。
