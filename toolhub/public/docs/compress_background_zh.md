# 图片压缩 — 背后的技术

图片是网页上最占流量的资源，没有之一。现在一个普通页面超过一半的体积都是图片贡献的。把图片压好不只是锦上添花——直接影响加载速度、移动端流量消耗、服务器带宽开销，以及 SEO 排名（Google 把页面速度纳入排名算法这件事大家都知道了）。

## 各种格式到底差在哪

**JPEG** 是照片场景的主力。有损压缩，底层用离散余弦变换（DCT），把肉眼不太敏感的高频信息扔掉。拍的照片用它很合适，但处理带文字的截图或者需要透明背景的图片就不行了。

**PNG** 是无损的，支持 alpha 透明通道。底层走 DEFLATE 算法，和 ZIP 压缩原理一样。图标、截图、UI 素材首选。但照片用它就惨了，体积能比 JPEG 大好几倍。

**WebP** 是 Google 搞出来的，有损无损都支持，透明度和动画也行。比 JPEG 小 25-35%，比 PNG 小约 26%。现在浏览器支持基本全覆盖了，连 Safari 从 14 版本就支持了。

**AVIF** 是最新的，基于 AV1 视频编码，比 JPEG 小 50%。问题是老浏览器还不支持。如果你面向的都是现代浏览器，直接上 AVIF 就行了。

## 压缩到底怎么做的

有损压缩靠这几招：色彩量化（减少颜色种类）、色度采样（人眼对亮度变化比色彩饱和度敏感得多，所以降低色彩分辨率看不太出来）、频率域压缩（DCT+量化，把高频细节精度降低）。

无损压缩换了个思路：预测编码（用相邻像素猜当前像素值）、熵编码比如 Huffman（对高频模式用更短的编码）、字典压缩比如 LZ77。

## 用的什么库

我们用的是 `browser-image-compression`，完全在浏览器里跑。不走服务器，不传任何图片。它在 Web Worker 里压缩，不会卡你的 UI。

```javascript
import imageCompression from 'browser-image-compression'

const options = {
  maxSizeMB: 1,            // 目标：不超过 1MB
  maxWidthOrHeight: 1920,   // 最大边长 1920px
  useWebWorker: true,       // 后台线程，不卡 UI
  fileType: 'image/jpeg',   // 输出格式
  initialQuality: 0.8       // 初始质量 80%
}

const compressedFile = await imageCompression(originalFile, options)
```

## 质量设置参考

| 质量 | 适合什么 | 大概省多少 |
|------|---------|-----------|
| 90%+ | 商业摄影、需要打印的 | ~20-30% |
| 75-90% | 网站头图、博客配图 | ~40-60% |
| 60-75% | 缩略图、预览图 | ~60-70% |
| 40-60% | 只用来看个大概的小图 | ~70-80% |

提醒一句：PNG 本质是无损格式，压低质量对它的压缩效果远不如 JPEG。如果不需要透明背景，把 PNG 转成 JPEG 再压缩往往体积更小。
