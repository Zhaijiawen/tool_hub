# 正则表达式测试器 — 使用示例

## 验证邮箱

**模式：** `^[\w.-]+@[\w.-]+\.[a-z]{2,}$`
**标志：** `i`

这是「99% 注册表单够用」的模式。它检查 `@` 前面有东西、后面有东西、顶级域名至少两个字母。

| 输入 | 匹配？ | 原因 |
|---|---|---|
| `user@example.com` | 是 | 标准邮箱，没悬念 |
| `user.name+tag@domain.co` | 是 | 本地部分的点和加号都合法 |
| `user@domain` | 否 | 缺少顶级域名，`domain` 单独不是有效域 |
| `@domain.com` | 否 | `@` 前面没东西，本地部分是必需的 |

如果你在表单校验里还想抓住 `user@gmial.com` 这类手误，那就得额外加一层拼写检查——正则自己搞不定这个。

## 从文本中提取所有数字

**模式：** `\d+`
**标志：** `g`

这属于高频模式。它把字符串里的每一段连续数字都拉出来，爬价格、解析日志、从混合文本里提取 ID 时经常用。

**输入：** `订单42包含3件商品，共计150.00元`
**匹配结果：** `42`、`3`、`150`、`00`

注意 `150.00` 给出了两个匹配——`150` 和 `00`——因为 `.` 不是数字。如果你想捕获完整的小数，得用 `\d+\.?\d*`。小小改动，结果天差地别。

## 匹配 ISO 日期

**模式：** `\b\d{4}-\d{2}-\d{2}\b`
**标志：** `g`

`\b` 单词边界在这里起了关键作用——它防止模式在更多内容中间截取匹配，比如 `2024-03-15T14:30:00Z`。不加边界的话，你会拿到一个 ISO 时间戳里日期部分的部分匹配。

**输入：**
```
会议时间 2024-03-15，截止日期 2024-04-01。
```
**匹配结果：** `2024-03-15`、`2024-04-01`

这个模式故意写得宽松——它也会匹配 `2024-99-99`，即使这根本不是个有效日期。需要严格校验日期的话你得做范围检查，而这件事说实话在代码里做比在正则里做合适。用正则抽取候选日期字符串，再程序化校验它们。

## 捕获姓和名

**模式：** `(\w+)\s(\w+)`
**标志：** （不需要）

分组让你从匹配中提取结构化数据，而不只是知道有东西匹配了。

**输入：** `张三 李四`
**第 1 组：** `张三`
**第 2 组：** `李四`

这是所有姓名翻转模式的基石。要用逗号把姓和名对调，用同样的模式，替换字符串写 `$2, $1`——搞定，`李四, 张三`。同样思路适用于重排电话号码、地址行，或者任何需要调整组件顺序的数据。

## 从 CSS 里找十六进制颜色

**模式：** `#[0-9a-fA-F]{3,6}\b`
**标志：** `gi`

**输入：** `body { color: #333; background: #f0f0f0; border: 1px solid #ff6600; }`
**匹配结果：** `#333`、`#f0f0f0`、`#ff6600`

`{3,6}` 量词同时覆盖简写（`#333`）和完整（`#ff6600`）的十六进制颜色。末尾的 `\b` 防止匹配到属于更长标识符的部分颜色值。
