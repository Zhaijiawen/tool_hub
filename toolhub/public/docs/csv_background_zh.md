# CSV 和 TSV：数据交换的通用格式

CSV 存在了几十年，而且还会继续存在下去。它是系统之间交换表格数据的最小公分母。但正确解析 CSV 其实比看上去复杂得多。

## CSV 和 TSV 的区别：就是分隔符不同

CSV 用逗号。TSV 用制表符。结构上没有其他区别。但分隔符的选择很重要，因为它决定了什么需要转义。

| 分隔符 | 字符 | 常见场景 |
|---|---|---|
| 逗号 | `,` | Excel、Google Sheets、通用 CSV |
| 制表符 | `\t` | 数据库 dump、MySQL 导出 |
| 分号 | `;` | 欧洲 Excel（那里逗号是小数点） |
| 竖线 | `\|` | 自定义日志格式 |
| 空格 | ` ` | nginx/apache 日志 |

## 为什么解析 CSV 比看起来难

### 1. 字段里包含分隔符

字段值本身有逗号的时候，用双引号包起来：

```
姓名,城市,备注
张三,"北京, 上海","经常出差，跨城办公"
```

不加引号的话，"北京" 和 "上海" 会被当成两列。

### 2. 字段里包含换行

引号包裹的字段可以跨多行：

```
id,描述
1,"第一行
第二行"
```

这意味着不能简单按 `\n` 切行再按 `,` 切列。解析的时候得跟踪当前是否在引号内。

### 3. 双引号转义

字段内部的双引号用两个连续的双引号表示：`""` 等于一个字面的 `"`：

```
name,quote
Bob,"他说""你好"""
```

### 4. 编码问题

CSV 文件可能是 UTF-8、GBK（中文 Windows 常见）、UTF-8 with BOM、Latin-1 或任何其他编码。编码跟解析器预期的不匹配，非 ASCII 字符就乱码。

## RFC 4180：事实标准

RFC 4180 把大多数 CSV 工具共同遵循的规则形式化了：

1. 每条记录一行，以 CRLF 结尾
2. 最后一条记录可以有也可以没有结尾换行
3. 第一行可选作为表头
4. 字段用逗号分隔
5. 包含逗号、双引号或换行的字段必须用双引号包起来
6. 引号字段内的双引号用 `""` 转义

现实中的 CSV 大多是"RFC 4180-ish" -- 差不多符合但很少 100% 合规。真实数据永远是乱的。
