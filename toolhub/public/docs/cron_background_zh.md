# Cron 表达式解析 - 技术背景

## 什么是 Cron

Cron 是 Unix/Linux 系统中的一个时间任务调度守护进程，允许用户在指定的时间点或时间间隔自动执行命令或脚本。"Cron" 名称来源于希腊语 "chronos"（时间）。

## Cron 表达式格式

### 标准 5 字段格式（Unix Cron）

```
┌───────── 分钟 (0 - 59)
│ ┌─────── 小时 (0 - 23)
│ │ ┌───── 日期 (1 - 31)
│ │ │ ┌─── 月份 (1 - 12)
│ │ │ │ ┌─ 星期几 (0 - 7，0 和 7 都表示周日)
│ │ │ │ │
* * * * *
```

### Quartz 6 字段格式（含秒）

```
┌────────── 秒 (0 - 59)
│ ┌──────── 分钟 (0 - 59)
│ │ ┌────── 小时 (0 - 23)
│ │ │ ┌──── 日期 (1 - 31)
│ │ │ │ ┌── 月份 (1 - 12)
│ │ │ │ │ ┌ 星期几 (1 - 7，1 = 周日)
│ │ │ │ │ │
* * * * * *
```

## 特殊字符说明

| 字符 | 含义 | 示例 |
|------|------|------|
| `*` | 任意值 | `* * * * *` = 每分钟 |
| `,` | 枚举多个值 | `1,15 * * * *` = 每小时第1、15分 |
| `-` | 范围 | `1-5 * * * *` = 每小时第1到5分 |
| `/` | 步进 | `*/5 * * * *` = 每5分钟 |
| `?` | 不指定（日期/星期） | Quartz 专用 |
| `L` | 最后 | `L` 在日期字段 = 月最后一天 |
| `W` | 最近工作日 | `15W` = 最近15号的工作日 |
| `#` | 第几个星期几 | `3#2` = 第2个星期三 |

## 常见 Cron 表达式

| 表达式 | 含义 |
|--------|------|
| `* * * * *` | 每分钟执行 |
| `0 * * * *` | 每小时整点执行 |
| `0 0 * * *` | 每天午夜执行 |
| `0 9 * * 1-5` | 工作日上午9点执行 |
| `0 0 1 * *` | 每月1号午夜执行 |
| `0 0 * * 0` | 每周日午夜执行 |
| `*/5 * * * *` | 每5分钟执行 |
| `0 8,12,18 * * *` | 每天8点、12点、18点执行 |
| `0 0 1 1 *` | 每年1月1日执行 |

## Cron 的工作原理

Cron 守护进程每分钟检查一次所有已注册的任务（称为 crontab 条目），对比当前时间是否匹配任务的时间表达式，匹配则执行对应命令。

## 不同平台的 Cron 实现

### Linux Cron (Vixie Cron)
最常见的 Unix Cron 实现，使用5字段格式，支持 `@reboot`、`@daily` 等预设关键字。

### Quartz Scheduler（Java）
Java 生态中最流行的任务调度库，使用6字段格式（含秒），支持 `L`、`W`、`#` 等额外特殊字符。

### Spring @Scheduled
Spring Framework 中的注解式调度，支持标准 Cron 表达式和 `fixedDelay`/`fixedRate` 方式。

### Node.js node-cron
Node.js 生态的 Cron 库，遵循 Unix 5字段格式。

### GitHub Actions 中的 Cron
GitHub Actions 使用 UTC 时区的5字段 Cron 表达式来配置定时工作流。

## 注意事项

1. **时区问题**：Cron 通常以服务器本地时区运行，需要注意夏令时带来的问题
2. **漏执行问题**：如果服务器关机时跳过了某个执行时间，任务不会补执行
3. **并发问题**：如果任务运行时间超过执行间隔，可能会产生并发执行，需要加锁处理
4. **最小粒度**：标准 Unix Cron 最小执行粒度为1分钟，需要更高频率的任务需使用 Quartz 或自定义实现
