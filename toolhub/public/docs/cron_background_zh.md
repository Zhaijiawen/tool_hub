# Cron 表达式：那五个星号到底什么意思

配置过 Linux 定时任务、GitHub Actions 工作流或者 Spring Boot 调度任务的人，都盯着过类似 `0 9 * * 1-5` 这种东西，然后祈祷自己没写错。来拆一下每个字段的作用。

## 五个字段（标准 Unix Cron）

```
┌───────── 分钟 (0-59)
│ ┌─────── 小时 (0-23)
│ │ ┌───── 日期 (1-31)
│ │ │ ┌─── 月份 (1-12)
│ │ │ │ ┌─ 星期 (0-7，0 和 7 都表示周日)
│ │ │ │ │
* * * * *
```

`* * * * *` 意思是"每月的每一天的每一小时的每一分钟"都执行。`*` 是通配符，匹配所有值。

Quartz（Java 生态）在前面多加了一个秒字段变成 6 个字段。Quartz 的星期字段用 1-7（1=周日），跟 Unix cron 不一样，踩过坑的人都记得。

## 特殊字符

| 字符 | 作用 | 示例 |
|---|---|---|
| `*` | 匹配所有值 | `* * * * *` = 每分钟 |
| `,` | 枚举多个值 | `1,15 * * * *` = 每小时的第 1 和第 15 分钟 |
| `-` | 范围 | `1-5 * * * *` = 每小时第 1 到第 5 分钟 |
| `/` | 步进 | `*/5 * * * *` = 每 5 分钟 |
| `?` | 不指定（Quartz） | 日期和星期冲突时用 |
| `L` | 最后一个（Quartz） | 日期字段里 = 当月最后一天 |
| `W` | 最近工作日（Quartz） | `15W` = 离 15 号最近的工作日 |
| `#` | 第几个（Quartz） | `3#2` = 当月第 2 个周三 |

## 你会背下来的几个表达式

| 表达式 | 含义 |
|---|---|
| `* * * * *` | 每分钟（不注意的话 CPU 直接拉满） |
| `0 * * * *` | 每小时整点 |
| `0 0 * * *` | 每天凌晨 |
| `0 9 * * 1-5` | 工作日上午 9 点 |
| `0 0 1 * *` | 每月 1 号凌晨 |
| `0 0 * * 0` | 每周日凌晨 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 8,12,18 * * *` | 每天 8 点、12 点、18 点 |
| `0 0 1 1 *` | 每年 1 月 1 日 |

## Cron 出现在哪些地方

- **Linux crontab**：原始出处。5 字段格式，支持 `@reboot`、`@daily`、`@weekly` 这些宏。
- **Quartz Scheduler**（Java/Spring）：6 字段格式，带秒。额外支持 `L`、`W`、`#`。
- **Spring @Scheduled**：用 cron 表达式，可选的第六个字段是秒。
- **GitHub Actions**：5 字段 UTC 时间的 cron。工作流的 `schedule` 触发器用它。
- **Kubernetes CronJob**：5 字段格式，写在 CronJob 的 `schedule` 字段里。
- **node-cron**（Node.js）：5 字段格式，options 里可以指定时区。

## 踩坑指南

1. **时区**：Cron 默认用服务器本地时区。服务器在 UTC 你写 `0 9 * * *`，实际执行时间跟你以为的 9 点可能差好几个小时。GitHub Actions 的 cron 永远是 UTC。
2. **日期和星期同时指定**：标准 cron 里，如果你同时指定了日期和星期，满足任意一个就触发。不是两者都满足。好多人在这栽过。Quartz 用 `?` 解决了这个问题。
3. **最小粒度 1 分钟**：标准 cron 做不到"每 30 秒执行一次"。要做秒级的得用 Quartz 或者自己写循环。
4. **漏执行**：服务器在任务该执行的时候恰好关机了，等它重启不会补执行。Linux 上的 Anacron 可以处理这种日/周/月级任务的补执行。
