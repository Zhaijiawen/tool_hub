# 查找与替换 — 技术背景

查找替换这种事，平时想不起来，真需要的时候你就知道它有多救命了。清理 CSV 数据、重构配置文件里的变量名、从抓取内容中剥掉标记——文本工作流里少不了它。

核心逻辑很简单：拿一个搜索词，扫一遍文本，把每处匹配换成替换字符串。有意思的地方在于搜索词可以是什么：纯字面文本，或者一套描述整类字符串的正则模式。

## 纯文本 vs. 正则

纯文本搜索就是字面意思——你的搜索词必须在原文中逐字出现。快、可预测、不会翻车，适合修个拼写错误或重命名单个常量这种直来直去的活。

正则模式把搜索框变成一个模式匹配引擎。你不再找某一个特定的字符串，而是描述你要匹配的东西长什么样：

```
\d+        → 一个或多个数字（任意数字）
[a-z]+     → 一个或多个小写字母
\bword\b   → 精确匹配单词 "word"——不会误伤 "password"
(foo|bar)  → "foo" 或 "bar" 中的一个
```

取舍很明显：纯文本更简单、不容易出错；正则在一条表达式里覆盖的面大得多，但需要你懂它的语法。大多数人从纯文本开始，搜到花样变多时再切正则。

## 替换怎么运作的

引擎找到匹配后，用你的替换字符串替代匹配文本。听着简单。但用了正则，替换字符串可以通过 `$1`、`$2` 引用模式里的捕获组——到这一步才算真正有意思。

```
模式：      (\w+)\s(\w+)
输入：      张三 李四
替换为：    $2, $1
结果：      李四, 张三
```

模式里的括号把 "张三" 捕获为 `$1`，"李四" 捕获为 `$2`，替换字符串重新排列了它们。同样的招数适用于日期格式转换、地址行重组，或者任何需要调整组件顺序而又不能丢数据的场景。

JavaScript 里还有 `$&` 代表完整匹配，`` $` `` 和 `$'` 代表匹配前后内容，不过实际用得少一些。

## 大小写和范围控制

两个设置改变搜索行为：

- **区分大小写**：大小写敏感模式下，`hello` 不认 `Hello` 和 `HELLO`。不区分就全都能匹配。大多数文本清洗用不区分就够了——但重构代码时（`userName` 和 `UserName` 是不同的标识符），大小写敏感就很关键。
- **全部替换 vs. 替换首个**：「全部替换」把每一处都换了——全局重构该用它。「替换首个」只处理第一个匹配，适合你知道只有一处或者想手动逐步检查的场景。

## 常见场景

| 场景 | 查找 | 替换 |
|---|---|---|
| 变量重命名 | `oldVar` | `newVar` |
| 修正拼写 | `teh` | `the` |
| 日期格式转换 | `(\d{4})-(\d{2})-(\d{2})` | `$3/$2/$1` |
| 去除 HTML 标签 | `<[^>]+>` | *（留空）* |
| 去除行尾空格 | `\s+$` | *（留空）* |
| 统一换行符 | `\r\n` | `\n` |

去行尾空格这个是最低调但最实用的模式之一——lint 工具天天抱怨它，走一遍这个正则整个文件就干净了。
