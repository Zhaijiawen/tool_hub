# 进制转换器 - 使用示例

## 标准转换

### 十进制转十六进制
`255`（十进制）转十六进制 = `FF`
`4096`（十进制）转十六进制 = `1000` -- 刚好是 16 的幂次边界

### 十六进制转二进制
`A5`（十六进制）转二进制 = `10100101`
每个十六进制字符精确对应 4 个二进制位：A=1010, 5=0101。拼起来就是 `1010 0101`。

### 八进制转十进制
`755`（八进制）转十进制 = `493`
这就是 `chmod 755` 背后的数值。7 x 64 + 5 x 8 + 5 = 493。

## 非标准进制

### 三进制
`210`（三进制）转十进制 = `21`
2 x 9 + 1 x 3 + 0 = 21

### 五进制
`123`（五进制）转十进制 = `38`
1 x 25 + 2 x 5 + 3 = 38

### 七进制
`100`（七进制）转十进制 = `49`
7^2 = 49

### 二十进制
`10`（二十进制）转十进制 = `20`
`1A`（二十进制）转十进制 = `30`（1 x 20 + 10）

### 三十六进制（字母数字）
`z`（三十六进制）转十进制 = `35` -- 最大的一位数字
`10`（三十六进制）转十进制 = `36` -- 进位点
`1z`（三十六进制）转十进制 = `71`（1 x 36 + 35）
`100`（三十六进制）转十进制 = `1296`（36^2）

## 真实应用

### 短链接 ID
Bitly 等服务用 base 62（0-9, a-z, A-Z）编码自增 ID。7 位 base-62 字符串可以表示 62^7 个值 -- 约 3.5 万亿个唯一 ID。

### 数据库分片键
需要在分片间分布 ID？把用户 ID 编码为 base N（N = 分片数），用最后一位做分片键。

### 紧凑错误码
`E2A`（三十六进制）比 `错误 2554` 直观得多，编码了相同的信息。`E` 前缀表示"错误"，`2A` 十进制是 94 -- 可以解读为错误类别 2、子错误 94。

### 位模式可视化
二进制输出让你看清确切的位模式：
- `15`（十进制）转二进制 = `1111` -- 低 4 位置位
- `240`（十进制）转二进制 = `11110000` -- 高 4 位置位，低 4 位清零
- `85`（十进制）转二进制 = `1010101` -- 交替模式
