# 文件压缩 — 技术背景

这个工具在你的浏览器里压缩和解压任意文件，支持三种主流算法：**Gzip**、**Brotli** 和 **Zstd**。文件从头到尾不离开你的设备——没有上传，没有服务器，压缩过程完全在本地完成。

## 三种算法怎么选

- **Gzip**：最通用。几乎任何系统、解压器都认识 `.gz`。本工具里 Gzip 走浏览器原生的 `CompressionStream` / `DecompressionStream`，是真正的流式处理，内存占用与文件大小无关，因此适合处理大文件。
- **Brotli**：谷歌的算法，压缩率通常比 Gzip 高 15-25%，但压缩更慢。适合长久存档。质量档位 1-11，默认 6。
- **Zstd**：Facebook 的算法，压缩率和速度都很均衡，质量档位 1-19，默认 3。适合既要体积又要速度的场景。

## 流式 vs 整读

这是本工具最关键的工程取舍：

- **Gzip 是流式的**。文件被切成 4MB 的小块逐块喂入压缩流，内存里始终只有一个块，所以 GB 级别的文件也能处理，并且可以随时取消。
- **Brotli / Zstd 走 WASM**，它们只提供「整块缓冲」接口——必须把整个文件一次性读进内存、压缩结果也同时驻留内存，峰值约为文件体积的 2 倍。因此这两种格式有内存上限。

## 为什么会有大小限制

Brotli / Zstd 在解压时，压缩包体积、解压后体积、以及单条缓冲会同时占用内存，超大文件会触及浏览器的 WASM 堆上限（通常 2-4GB）。所以工具设定了分级阈值：

- **安全上限 2GB**：超过则直接拦下，避免你等了几分钟结果浏览器内存溢出。
- **提醒阈值 500MB**：超过会提示内存峰值较高，但仍可尝试。

Gzip 因为是流式的，不设上限。

## 格式自动识别

解压时工具会读取文件头部 8 字节来猜测格式：Zstd 的魔数是 `28 B5 2F FD`，Gzip 是 `1F 8B`。识别成功后自动选对解压器，减少你试错。Brotli 没有标准魔数，需要你手动指定。

输出的扩展名：压缩为 `.gz` / `.br` / `.zst`，解压时自动去掉这些后缀（找不到则加 `.decompressed`）。
