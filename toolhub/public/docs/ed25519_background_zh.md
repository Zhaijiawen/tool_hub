# Ed25519 技术背景

Ed25519 是我认为当今最好的通用数字签名算法。速度快、签名紧凑（64 字节）、从根源上杜绝了困扰 ECDSA 的 nonce 重用灾难，而且设计刻意简单，这让实现很难犯错。如果你在构建需要签名的新项目，Ed25519 应该成为你的默认选择，除非有特殊理由选别的。

## Bernstein 的密码学哲学

Daniel J. Bernstein（djb）算得上是应用密码学领域的民间英雄。他设计算法有一套始终如一的哲学：纯软件就很快、不需要特殊硬件、恒定时间让时序攻击无从下手、简单到有能力的程序员可以对着规范正确实现。Ed25519 就是这种哲学的完美例证。

签名方案构建在 Edwards 曲线 edwards25519 上（与 Curve25519 双有理等价）。Edwards 曲线有个漂亮的特性：加法公式是"统一的"-- 同样的数学能同时处理两个不同点的加法和单个点的倍乘。这消除了 ECDSA 实现中根据两点是否相等做分支判断的逻辑，后者正是经典的侧信道漏洞来源。

## Ed25519 签名的工作原理

方案大量使用 SHA-512（这就是 EdDSA 中的 "Ed" -- 用哈希函数的 Edwards 曲线 Schnorr 签名变体）：

**密钥生成**极其简单。32 字节随机种子用 SHA-512 哈希。低 32 字节成为私钥标量（经过 clamping 处理防止小子群攻击），高 32 字节用作签名 nonce 生成的前缀。公钥是私钥标量乘以基点。

**签名**是确定性的 -- 没有随机 nonce 需要管理。签名 nonce 通过 SHA-512(prefix || message) 来派生，其中 prefix 是密钥生成时 SHA-512 输出的上半部分。这是杀手级特性：因为 nonce 是确定性的，你永远不可能意外重用 nonce。ECDSA 那种通过 nonce 重用提取私钥的攻击根本不适用于 Ed25519。

签名本身是 (R, s) -- 点 R = rG（其中 r 是确定性 nonce），s = r + H(R || A || M) * a (mod l)，其中 a 是私钥、A 是公钥、M 是消息、l 是曲线阶。总大小：64 字节。

**验证**检查 sG = R + H(R || A || M) * A。两次标量乘法加一次哈希 -- 非常快。

## 64 字节签名为什么这么好

对比一下：256 位 ECDSA 签名通常是 70-72 字节（DER 编码）或 64 字节（原始 r||s）。RSA-2048 签名是 256 字节。Ed25519 的 64 字节很难被超越。这种紧凑性在把签名放到 HTTP 头、区块链交易（每个字节都花 gas）、或者 MTU 限制严格的嵌入式协议中时非常重要。

## 批量验证 -- 隐藏的超能力

Ed25519 支持批量验证：你可以在大约验证两个签名的时间之内验证数十甚至数百个签名。窍门是验证检查 sG - H(R||A||M)A = R，你可以把多个签名的这些方程求和，用多标量乘法一次检查一个大方程。这对区块链节点、证书透明度日志和任何验证大量签名的系统来说意义重大。

大多数密码库把批量验证作为可选功能暴露。它确实有稍有不同的失败模式（一个精心构造的签名集合可能掩盖批处理中单个的坏签名），所以你需要权衡性能提升和微妙的安全性取舍。对已经信任大多数签名有效的高吞吐验证场景，这是一个很好的优化。

## 采用和生态

Ed25519 现在到处都是。SSH 原生支持它并推荐优先于 RSA 和 ECDSA。TLS 1.3 在默认支持的签名算法中包含 Ed25519。Signal 协议用它做身份密钥。门罗币、Solana 和其他几种加密货币用 Ed25519 做交易签名。GPG 支持它。唯一的长期例外是 WebAuthn/FIDO2，而即使这个也正在添加 Ed25519 支持。

如果你从零开始，Ed25519 是显而易见的选择。如果你在维护现有的 ECDSA 系统，值得为迁移到 Ed25519 做计划（两种算法可以共存 -- 只需在现有 ECDSA 公钥旁边添加 Ed25519 公钥，当两者都可用时优先使用 Ed25519）。
