# Git Commit 生成器 - 使用教程

## 快速开始

Git Commit 生成器帮助你快速生成符合 Conventional Commits 规范的提交信息，无需记忆格式。

## 填写提交信息

### 步骤 1：选择提交类型

从下拉菜单中选择最匹配本次改动的类型：

- **feat** ✨ — 实现了新功能、新接口、新页面
- **fix** 🐛 — 修复了一个 Bug
- **docs** 📝 — 只改了文档或注释
- **style** 💄 — 调整了代码格式（空格、缩进），没改业务逻辑
- **refactor** ♻️ — 重构了某段代码，既不是新功能也不是 Bug 修复
- **perf** ⚡️ — 优化了性能
- **test** ✅ — 添加或修改了测试用例
- **chore** 🔧 — 修改了构建脚本、依赖、CI 配置等辅助工具

### 步骤 2：填写影响范围（可选）

`Scope` 是括号内的模块名，用来说明本次改动影响的模块，例如：

- `feat(auth): 新增短信验证码登录`
- `fix(payment): 修复金额精度问题`
- `refactor(user): 提取用户状态管理`

如果改动涉及全局或不好分类，可以留空。

### 步骤 3：写简短描述

`Subject` 是提交的核心说明，遵循以下原则：

- **动宾结构**：说明做了什么，如"新增用户头像上传功能"
- **不超过 72 字符**：超出后工具会实时提示
- **使用现在时**：推荐"修复登录 Bug"而非"修复了登录 Bug"

### 步骤 4：填写详细描述（可选）

`Body` 用于说明改动的原因和背景，适合复杂改动时补充：

```
重构了用户状态管理模块，将原来分散在各个组件中的状态
提取到统一的 Pinia store，减少了重复代码并提升了可维护性。
```

### 步骤 5：标记破坏性变更（可选）

如果本次改动会导致调用方需要修改代码（如删除接口、修改参数格式），请打开"破坏性变更"开关，并在说明中描述：

- 什么发生了变化
- 如何迁移（升级步骤）

### 步骤 6：关联 Issue（可选）

在 `Issues` 字段填写关联的 Issue 编号，如 `#123, #456`，生成的提交信息会自动添加 `Closes: #123, #456`。

## 复制提交信息

生成的提交信息会实时显示在预览区。点击：

- **复制完整 Commit**：复制包含标题、Body、Footer 的完整信息
- **仅复制标题行**：只复制第一行 `type(scope): subject`

## 历史记录

每次点击"复制完整 Commit"后，本次提交信息会自动保存到历史记录（最多保留 5 条）。

点击历史记录中的某条可以重新回填表单，方便参考相似的历史提交。

## 最佳实践

1. **一个提交只做一件事**：不要把"修复 Bug + 新增功能"混在一个提交里
2. **提交前检查预览**：确保 type 和描述准确传达了改动意图
3. **破坏性变更一定要注明**：方便 Code Review 和版本管理工具自动处理
4. **scope 保持一致**：项目组内统一 scope 的命名方式
