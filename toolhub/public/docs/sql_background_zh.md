# SQL — 幕后是怎么运作的

SQL 从 1970 年代活到现在。IBM 的研究员 Chamberlin 和 Boyce 搞出了 SEQUEL（后来改名 SQL），初衷是用接近自然英语的方式来跟数据库对话。Oracle 在 1979 年第一个商业化实现，从此 SQL 就成了关系型数据库的通用语言，没被替代过。

## 核心理念

SQL 是声明式的——你说「要什么」，数据库自己决定「怎么拿」。你写 `SELECT * FROM users WHERE active = true`，剩下的交给查询优化器：走哪个索引、用什么 join 策略、分配多少内存缓冲区，全不用你操心。

底层的关係模型也很简单：一切都是表（关係），有行有列。SQL 分成四种子语言来操作：

- **DDL** — `CREATE`、`ALTER`、`DROP`；管表结构
- **DML** — `SELECT`、`INSERT`、`UPDATE`、`DELETE`；99% 时间在写的东西
- **DCL** — `GRANT`、`REVOKE`；管权限
- **TCL** — `COMMIT`、`ROLLBACK`、`SAVEPOINT`；管事务

## SQL 为什么经久不衰

**ACID 事务。** 原子性、一致性、隔离性、持久性。两个账户之间转账，要么两边都更新成功，要么都不变。不会出现钱扣了但没收到的中间态。主流关系型数据库都保证这一点。

**约束保护数据。** 主键、外键、`NOT NULL`、`CHECK`、`UNIQUE`——数据库自己拒绝脏数据，比靠应用代码防 bug 靠谱得多。

**索引让查询飞起来。** 一个 B 树索引把 O(n) 的全表扫描变成 O(log n) 的查找。索引建对了，十亿行表也能毫秒查询。

## 主流选择

- **PostgreSQL** — 开发者的数据库。JSONB、全文搜索、窗口函数、CTE、扩展生态。新项目首选。
- **MySQL/MariaDB** — 撑起半个互联网。简单、快、读多写少的场景很强。LAMP 技术栈的默认数据库。
- **SQLite** — 它是一个库，不是服务器。嵌在你的手机、浏览器、各种应用里。零配置，单文件存储。
- **SQL Server / Oracle** — 企业标配，授权费不便宜。配套工具生态庞大。

## 没人告诉你的坑

**NULL 很诡异。** `NULL = NULL` 的结果不是 true，是 NULL。要用 `IS NULL` / `IS NOT NULL`。聚合函数会跳过 NULL，但 `COUNT(*)` 不会。

**索引不是免费的。** 每建一个索引，写入都会变慢，因为索引也要更新。给查询的列建索引，别给所有列都建。用 `EXPLAIN`（或 `EXPLAIN ANALYZE`）看实际执行计划。

**所有查询都参数化。** 绝对不要把用户输入拼接到 SQL 字符串里。参数化查询（预编译语句）免疫 SQL 注入，因为查询结构在填值之前就定死了。

**事务便宜，但别拖太久。** 开着事务等于锁着行。长时间运行的事务是生产环境莫名变慢的头号元凶。事务越短越好。
