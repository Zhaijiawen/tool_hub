# 编码方案 -- 它们是什么以及为什么重要

编码经常和加密混淆，但它们是完全不同的事情。编码把数据转换成另一种表示形式以便传输或存储 -- 它不隐藏信息，只是改变格式。Base64、Base32、URL 编码、十六进制编码：这些都是编码方案。任何人都能解码，因为没有密钥。

## Base64

Base64 是最常见的二进制转文本编码。每 3 字节输入变成 64 字符字母表（A-Z、a-z、0-9、+、/）中的 4 个 ASCII 字符。这让二进制数据能在纯文本通道中安全传输，比如邮件（MIME）、JSON、XML 和 HTTP 头。

原理：3 字节 = 24 位。分成四个 6 位块（2^6 = 64，所以叫 "Base64"）。每个 6 位值映射到字母表中的一个字符。如果输入不是 3 字节的倍数，用 `=` 字符填充。两个 `=` 意味着 1 字节填充，一个 `=` 意味着 2 字节。

标准变体用 `+` 和 `/` 作为最后两个字符，`=` 用于填充。URL 场景下，Base64url 把 `+` 换成 `-`，`/` 换成 `_`，通常省略填充。JWT 用的就是这个。

常见错误：以为 Base64 提供任何安全性。不提供。一行代码就能在任何语言中解码 Base64。它纯粹是传输编码。

## 十六进制编码

十六进制把每个字节编码为两个十六进制数字（0-9、a-f）。值为 255 的字节变成 `ff`。十六进制字符串是原始数据的两倍长，处理大数据不如 Base64 高效，但人类可读性好得多。调试工具、哈希展示和密钥几乎都用十六进制。

## URL 编码（百分号编码）

URL 编码把不安全字符替换为 `%` 后跟十六进制 ASCII 值。空格变成 `%20`，`#` 变成 `%23`。这就是为什么你可以在 URL 查询字符串中放任意数据而不破坏 URL 语法。

## Base32 和其他变体

Base32 使用 32 字符字母表（A-Z、2-7），每个字符编码 5 位。效率不如 Base64，但避免了大小写敏感和视觉相似字符（不会混淆 0/O 或 1/I/l）。用于 OTP 密钥和一些 DNS 相关编码。

## 编码 vs 加密 vs 哈希

这个区别老有人搞混：

- **编码**：无密钥可逆。Base64、十六进制、URL 编码。只是改变格式。
- **加密**：有密钥可逆。AES、ChaCha20。隐藏内容。
- **哈希**：单向。SHA-256、bcrypt。无法逆转（设计如此）。

如果你在存储密码，用哈希（bcrypt/Argon2），不是编码。如果你在保护数据，用加密（AES），不是编码。编码只是为了通过纯文本通道安全传输数据 -- 仅此而已。
