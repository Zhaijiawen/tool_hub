# AI Token 计算器 — 技术背景

大语言模型（LLM）不是按"字符"计费的，而是按 **token** 计费。Token 是模型分词器（tokenizer）把文本切出来的最小单位——一个英文单词常常被切成 1-2 个 token，中文通常按字或词切，一个汉字约 1 个 token。各家模型的分词器不同，同样的文本在不同模型里 token 数也不一样。

本工具的目标很简单：**在你写 prompt 之前，就知道自己会用掉多少 token、要花多少钱**——而且全程在你的浏览器里完成，文本不上传任何服务器。

## 分词器是怎么工作的

主流开源分词算法是 **BPE（Byte Pair Encoding）**。它从字符出发，反复把"最常相邻出现的字节对"合并成一个新 token，直到达到词表上限。模型在训练时就固定了这套映射，所以同一段文本的分词结果是确定的。

- **OpenAI** 的 GPT-3.5 / GPT-4 / 4-Turbo 用 `cl100k_base`；GPT-4o 及之后的新模型（含 o1 / o3 系列）改用 `o200k_base`，词表更大。
- **Anthropic（Claude）** 使用自有的分词器，并未公开。本工具用 `cl100k_base` 做**近似估算**——数量级准确，但精确值会有偏差。界面会明确标注这是近似值。

## 为什么在本地算

`tiktoken` 的 BPE rank 数据被打包进了页面（cl100k_base 约 1 MB，o200k_base 约 2.2 MB），随路由懒加载。整个分词过程纯 CPU 运算，几万字的文本也是毫秒级。

- **隐私**：你的 prompt 永远不离开浏览器，适合含敏感信息的文本。
- **零延迟**：不用等网络往返，输入即出结果。
- **离线可用**：rank 文件已随站点自托管，不依赖任何 CDN。

代价是：首次打开工具时需要下载约 1-3 MB 的分词数据（之后浏览器缓存，再次打开秒开）。这是与云端分词服务唯一的取舍。

## 费用的参考性质

工具内置的价格是各厂商公开价的**参考值**（单位：美元 / 每百万 token）。价格会随厂商调整而变化，请以你账单上的实际金额为准。费用栏显示的是"把当前文本当作输入（prompt）"的估算；如果你还想估算模型输出（completion）的花费，可参考 out 一列的单价自行相乘。

## 为什么传统工具站没有这个

Token 计费是 AI 时代才普及的概念，绝大多数"在线工具集合"站点仍停留在格式转换、加解密等老需求上。而 AI 用户每天都需要估算 prompt 成本——这是一个"大众需要、传统站没有"的典型差异化场景。
