# HTML 实体编解码 — 技术原理

HTML 里有一批字符有特殊含义：`<` 和 `>` 界定标签，`&` 起始实体引用，引号界定属性值。要在页面里**显示**这些字符本身，而不是让浏览器把它们当语法，就得用实体引用——一套「&开头、分号结尾」的转义序列。

## 常见实体

| 字符 | 实体 | 场景 |
|---|---|---|
| `<` | `&lt;` | 在页面展示代码片段 |
| `>` | `&gt;` | 同上 |
| `&` | `&amp;` | 文本里含 & 号（不转义会被当成实体起始） |
| `"` | `&quot;` | 属性值内含引号 |
| `'` | `&#39;` | 同上，单引号 |
| 空格 | `&nbsp;` | 不换行的连续空格 |

也可以用数字引用：`&#60;`（十进制）或 `&#x3C;`（十六进制）等价于 `&lt;`。三种写法浏览器都认。

## 编码 vs 解码

- **编码**：把 `<script>alert(1)</script>` 变成 `&lt;script&gt;alert(1)&lt;/script&gt;`——现在这段文本可以安全地显示在页面上，浏览器不会执行它。
- **解码**：反过来，把 `&lt;b&gt;` 变回 `<b>`——把网页上复制来的实体文本还原成可读字符。

## 安全边界（重要）

实体编码是**显示层**的转义，不是完备的 XSS 防护。把用户输入实体编码后插入 HTML 能挡住「`<script>` 直接被解析」这一类攻击，但属性上下文（`href="..."` 里的 `javascript:` URL）、事件属性、以及解码时机不当都会留下口子。生产环境的防 XSS 请用经过审计的库（DOMPurify 等），并按上下文选择正确的转义策略（HTML 体 / 属性 / JavaScript / URL 各自不同）。
