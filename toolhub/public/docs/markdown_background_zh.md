# Markdown — 幕后原理

Markdown 是 John Gruber 在 2004 年搞出来的。核心理念一直没变：用纯文本写内容，人直接读得懂，解析器负责转成 HTML。妙就妙在那些标记字符（`#`、`*`、`[]`）本身看起来就很自然，不渲染也不碍眼。随便用个文本编辑器打开 `.md` 文件，照样能看懂。

## 解析器怎么干活

把 Markdown 喂给转换器，大致走这么几步：先按块切分——段落、标题、代码围栏、列表各归各的；然后逐块做行内解析，`**` 包起来的内容变成 `<strong>`，`[text](url)` 变成 `<a>` 标签。最终吐出一串 HTML。市面上的解析器（`marked`、`markdown-it`、`remark`）基本都走这个两遍流程，只是实现细节各有不同。

## 你真正会碰到的方言

Gruber 从来没给 Markdown 写过正式规范，所以冒出来一堆变种。主要的几个：

- **CommonMark** 最接近官方标准，严格、可预测。你的 Markdown 在 CommonMark 下能过，到其他地方大概率也没问题。
- **GitHub Flavored Markdown (GFM)** 加了表格、任务列表、删除线和自动链接。GitHub、GitLab 以及大多数开发者平台用的都是它。
- **MDX** 允许在 Markdown 里直接嵌入 JSX 组件——React 生态的文档站（Docusaurus、Nextra）就是这么玩的。
- **kramdown** 是 Jekyll 的默认解析器，GitHub Pages 背后也是它。

## 日常高频语法

### 标题

```markdown
# 一级标题 — 页面大标题
## 二级标题 — 章节
### 三级标题 — 小节
#### 四级标题 — 很少用到，但需要时随时可用
```

用 ATX 风格（`#`），别用 Setext 风格（`===` 下划线）。所有解析器对 ATX 的支持都一致。

### 强调

```markdown
**粗体**     — 渲染为 <strong>
_斜体_       — 渲染为 <em>
~~删除线~~   — 仅 GFM 支持
***粗斜体*** — 两者叠加
```

### 列表

无序列表 `-`、`*`、`+` 都行，但同一个文档里挑一种用到底。

```markdown
- 第一项
- 第二项
  - 两个空格缩进嵌套
  - 继续嵌套

1. 第一步
2. 第二步
   1. 子步骤（有序子列表需要三个空格缩进）
```

### 链接和图片

```markdown
[行内链接](https://example.com)
[带标题的链接](https://example.com "悬停提示")
[引用式链接][ref]

![替代文字](image.png)
![替代文字](image.png "标题")

[ref]: https://example.com
```

同一个 URL 要引用多次的时候，引用式链接比行内链接清爽得多。

### 代码

行内：`` `const x = 1` `` — 如果代码本身包含反引号，用双反引号包裹。

围栏代码块：

````markdown
```javascript
const greet = (name) => `Hello, ${name}`;
```
````

语言标签一定要写，预览时的语法高亮全靠它。

### 表格（GFM）

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|------:|
| 单元格 | 内容 | ¥3.00 |
| 单元格 | 内容 | ¥6.00 |
```

分隔行里的冒号控制对齐方向。两边的竖线不是必须的，但加上源码更好读。

### 引用块

```markdown
> 单行引用

> 多行引用块
> 可以跨多个段落
>
> 第二段仍然在引用内
```

### 任务列表（GFM）

```markdown
- [x] 已完成
- [ ] 待处理
- [ ] 另一项待处理
```

### 水平分隔线

用 `---` 单独成行。别用 `***` 或 `___`——`---` 认可度最高。

## 容易踩的坑

**列表前不空行。** 如果忘了在列表前加空行，解析器可能不把它当列表，而是拼到上一段里。

**列表内的代码块缩进。** 列表项里的围栏代码块需要额外缩进。用围栏（` ``` `）比用缩进式代码块干净得多，不会把排版搞乱。

**转义。** Markdown 不是所有地方都用反斜杠转义——`\*` 可以转义星号，但代码区里根本不需要转义。

**HTML 透传。** 大多数解析器允许原生 HTML，所以 `<div>`、`<span>` 甚至 `<details>` 都能用。块级 HTML 元素前后要加空行才能正确渲染。
