# User Agent 解析器 — 使用教程

UA 解析器做两件事：自动显示你浏览器的 User Agent 字符串，以及让你粘贴任意其他 UA 字符串进来分析。

## 读取你自己的 UA

页面加载时，工具从你的浏览器抓取 `navigator.userAgent` 并显示出来。你会在顶部看到原始字符串，下方是解析后的拆分结果：浏览器名称和版本、操作系统、设备类型（桌面端、移动端或平板）、渲染引擎。

这是查你的浏览器到底向每个网站发送了什么的最快方式。如果你曾怀疑自己的「Chrome」到底是真 Chrome 还是某个 Chromium 分支，看解析结果里的浏览器字段就清楚了。

## 解析任意 UA 字符串

如果你在排查用户反馈的问题或分析服务器日志，把他们的 UA 字符串粘贴到输入框。解析器会用同样的方式拆解它。适用场景：
- 用户报了一个 bug，你想知道他的确切浏览器和 OS 版本
- 服务器日志里出现了一个奇怪的 UA，你需要搞清楚它是哪个客户端
- 你在调查爬虫流量，想看看某个爬虫声称自己是谁

## 去哪里找 UA 字符串

如果你在收集 UA 来解析，获取来源如下：
- **浏览器 DevTools**：打开 Console，输入 `navigator.userAgent`——输出正是解析器处理的格式
- **Network 标签**：任何 HTTP 请求的请求头区域都显示 `User-Agent` 头
- **服务器日志**：大多数 Web 服务器（nginx、Apache）默认记录 UA 字符串
- **分析工具**：Google Analytics、Matomo 等服务会抓取每个访客的 UA 字符串

## 理解解析后的字段

解析器把混乱的 UA 字符串提炼成具体的字段：

- **浏览器**和版本通过寻找 `Chrome/120`、`Firefox/120`、`Safari/17` 这类标记来提取。当多个浏览器互相声称是对方时（Chrome 也声称自己是 Safari），解析器根据标记优先级识别真实浏览器。
- **操作系统**来自括号部分：`Windows NT`、`Mac OS X`、`iPhone OS`、`Android`、`Linux`。版本号格式因 OS 而异——Windows 用内部版本号，macOS 用下划线分隔的版本组件，iOS 和 Android 用简单的点号分隔版本。
- **设备类型**从 OS 推断：`iPhone` 或带 `Mobile` 标记的 `Android` 代表移动端，`iPad` 或不带 `Mobile` 的 `Android` 通常是平板，`Windows NT` 或 `Macintosh` 代表桌面端。
- **引擎**即渲染引擎：Blink、WebKit 或 Gecko。通过 `AppleWebKit`（有或无 `Chrome/`）或 `Gecko` 的存在来识别。

## 实际工作流

常见调试流：你收到一个 bug 反馈说「我手机上页面显示不对」。让用户打开工具，复制自己的 UA，发给你。贴进解析器，你立刻知道：iPhone 15 运行 iOS 17.2，Safari 17.2。现在你可以在精确的平台上复现问题，而不是猜来猜去。

服务端场景：如果你在写检查 UA 字符串的代码，先贴几个样本 UA 进解析器验证你的检测逻辑。解析器展示了一个正经解析库会提取出的结果，你可以把自己的正则或字符串匹配方案跟它对标。
