# JSON 格式化 - 使用教程

API 返回了一坨压缩的 JSON，或者从日志里捞出来一堆无从下眼的 JSON，需要格式化看看里面到底有什么。这个工具干的就是这个 -- 一键格式化、校验、美化。

## 怎么用

### 粘贴 JSON

把原始 JSON 贴到输入区。压缩的、半残的，都行。常见来源：

- API 响应体（DevTools 的 Network 面板直接复制）
- 带 JSON 行的日志文件
- 调试中的配置文件
- 数据库里翻出来的 JSON 字段

贴进去的大概长这样：
```json
{"name":"ToolHub","version":"1.0.0","features":["format","encrypt","convert"],"config":{"theme":"dark","language":"en"}}
```

### 点格式化

点一下按钮，自动展开加缩进：
```json
{
  "name": "ToolHub",
  "version": "1.0.0",
  "features": [
    "format",
    "encrypt",
    "convert"
  ],
  "config": {
    "theme": "dark",
    "language": "en"
  }
}
```

### 选缩进风格

大部分用 2 空格缩进（Prettier 默认也是这个，深层嵌套不容易飘到右边去）。4 空格对于浅层结构读起来更舒服。Tab 是老派做法。选一个，保持一致。

### 复制走人

格式化输出旁边点复制，贴到需要的地方。

## 校验器能抓出什么

格式化同时自动校验。常见错误：

**键没加引号** -- `{name: "value"}` 是 JavaScript，不是 JSON。工具会标出来，加上引号就完事。

**尾随逗号** -- 数组或对象最后多出来的逗号在 JS 里合法，JSON 里不行。很容易漏：
```json
// 不合法
{
  "a": 1,
  "b": 2,
}
```

**未转义的控制字符** -- JSON 字符串里的换行符必须是 `\n`，不能是真实的换行。从终端或者自动换行的编辑器复制 JSON 的时候经常碰到。

**括号不匹配** -- 500 行的 JSON 文件某个地方少了个 `}` 或 `]`。校验器会指出大致行号。

## 经验之谈

保留原始压缩 JSON 的备份。有时候需要对比原始和格式化版本来确认没改动。

超大 JSON（超过 1MB）浏览器可能会卡。浏览器端格式化器处理几 MB 内通常没问题，再大用 `jq` 或本地工具。

不要把格式化的 JSON 存到生产数据库 -- 白白浪费字节。调试时格式化，传输和存储时压缩。

如果 JSON 是别的工具生成的，注意非标准扩展。有些服务输出带注释、尾随逗号或单引号字符串的 JSON。工具会帮你揪出来 -- 这就是它的价值。
