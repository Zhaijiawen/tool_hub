# JSON 格式化 - 使用教程

API 返回了一坨压缩的 JSON，或者从日志里捞出来一堆无从下眼的 JSON，需要格式化看看里面到底有什么。这个工具干的就是这个 -- 一键格式化、校验、美化。

## 怎么用

### 粘贴 JSON

把原始 JSON 贴到输入区。压缩的、半残的，都行。常见来源：

- API 响应体（DevTools 的 Network 面板直接复制）
- 带 JSON 行的日志文件
- 调试中的配置文件
- 数据库里翻出来的 JSON 字段

贴进去的大概长这样：
```json
{"name":"ToolHub","version":"1.0.0","features":["format","encrypt","convert"],"config":{"theme":"dark","language":"en"}}
```

### 点格式化

点一下按钮，自动展开加缩进：
```json
{
  "name": "ToolHub",
  "version": "1.0.0",
  "features": [
    "format",
    "encrypt",
    "convert"
  ],
  "config": {
    "theme": "dark",
    "language": "en"
  }
}
```

### 复制走人

格式化后点复制按钮，贴到需要的地方。

## JSON / JSON5 切换

卡片标题右侧有一个 `[JSON → JSON5]` 按钮组，点击即可切换模式：

- **JSON**（默认）：标准 JSON 格式化，2 空格缩进，输出双引号键
- **JSON5**：支持注释、无引号键、尾逗号、单引号字符串。通过后端 Prettier 格式化，注释完整保留

JSON5 模式适用于 `.prettierrc`、`tsconfig.json`、`eslintrc` 等配置文件——这些文件本身就是 JSON5 格式，格式化了结构更清晰，注释也不会丢。

切换到 JSON5 后页面会显示三条提示，说明格式化后键引号可能被去除、短对象可能保持单行等行为。

## 常见写法要点

格式化是排版工具，不是语法校验器。以下问题帮你熟悉 JSON 和 JSON5 的语法边界：

**键没加引号** -- `{name: "value"}` 在标准 JSON 中非法，但在 JSON5 模式下合法。JSON 模式下格式化会验证键是否有双引号，不合法则报错。

**尾随逗号** -- 数组或对象最后多出来的逗号标准 JSON 不允许，JSON5 允许：
```json
// JSON 不合法，JSON5 合法
{
  "a": 1,
  "b": 2,
}
```

**括号不匹配** -- 某处少了个 `}` 或 `]`，格式化引擎解析失败会报错，但只能报告大致位置。

## 经验之谈

保留原始压缩 JSON 的备份。有时需要对比原始和格式化版本来确认没改动。

超大 JSON（超过 1MB）浏览器可能会卡。浏览器端格式化器处理几 MB 内通常没问题，再大用 `jq` 或本地工具。

不要把格式化的 JSON 存到生产数据库——白白浪费字节。调试时格式化，传输和存储时压缩。

碰到带注释、尾随逗号或单引号字符串的「JSON」文件——切到 JSON5 模式就行，不需要手动清理。
