# 图像处理 — 技术背景

图像工具完全在你的浏览器里运行，用的是 Canvas API。不会上传到服务器，不用等后端处理——一切在客户端完成。这点很重要，因为图片可能很大，而你大概不想让敏感照片离开你的设备。

## 浏览器能做什么

Canvas API 给你像素级的图像访问能力，所以这个工具不用任何外部库就能做很多事：

- **格式转换**：以一种格式读入图像（JPEG、PNG、WebP、AVIF、BMP、GIF），以另一种格式写出。浏览器原生处理编解码。
- **缩放和裁剪**：Canvas 让你把源图像数据画到任意尺寸的目标矩形里。重采样质量取决于浏览器的实现——Chrome 和 Firefox 默认都做双三次插值。
- **旋转和翻转**：Canvas 上的仿射变换处理旋转和镜像。数学运算在 GPU 里完成。
- **压缩质量控制**：JPEG 和 WebP 输出接受质量参数（0-1）。质量越低，文件越小，瑕疵越多。你可以实时预览这个取舍。

## 格式取舍

你实际会选的几种格式：

- **JPEG**：有损，不支持透明，适合照片。质量 80 是 Web 场景的最佳平衡点——视觉上跟 100 没区别但文件只有一半大。低于 60 就能看到瑕疵了。
- **PNG**：无损，支持完全 alpha 透明。最适合截图、logo、文字密集的图形和任何有锐利边缘的内容。照片场景下文件比 JPEG 大，但不会丢失任何细节。
- **WebP**：谷歌的格式。同时支持有损和无损，含透明通道，生成的文件比同等 JPEG/PNG 小 25-35%。浏览器支持已全面覆盖。
- **AVIF**：比 WebP 更好的压缩率（同等质量下通常再小 50%）。支持 HDR 和广色域。缺点是编码更慢，而工具在浏览器里运行，处理大图时你能感受到差别。

## 缩放质量的原理

把图像缩小时，浏览器要决定每个输出像素由哪些源像素贡献。默认是双三次插值——邻近像素的加权平均——大多数情况下看起来不错。

放大时没有新增信息可用，结果会显得模糊。浏览器没法凭空补上源图中不存在的细节。如果你需要大幅放大一张图，最好用专门的 AI 超分辨率工具。

## 为什么在客户端处理

工具从不把你的图像发送到任何地方。这不只是隐私特性——也是性能特性。一张 20 MB 的照片上传要花几秒，下载结果又要几秒。浏览器处理只要几毫秒。唯一的瓶颈是你设备的 CPU/GPU。

代价是：浏览器的图像编解码器是为速度优化，不是为把文件里每个字节都榨干。如果你需要极致压缩（比如生产环境的图像处理管道），服务器上跑 `imagemagick` 或 `sharp` 这类命令行工具效果更好。但日常一次性转换，浏览器绰绰有余。
