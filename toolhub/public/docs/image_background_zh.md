# 图像处理 — 技术背景

图像工具完全在你的浏览器里运行。多数操作用 Canvas API，WebP / AVIF 编码和 PNG 无损压缩用编译成 WebAssembly 的编码器。不会上传到服务器，不用等后端处理——一切在客户端完成。这点很重要，因为图片可能很大，而你大概不想让敏感照片离开你的设备。

## 工具矩阵

| 工具 | 底层技术 | 能做什么 |
|---|---|---|
| 格式转换 | Canvas API | JPEG / PNG / GIF 互转，批量最多 10 张，带质量滑块与尺寸调整 |
| WebP / AVIF 转换 | Squoosh WASM 编码器 | 生成 WebP / AVIF，同画质下比 JPEG/PNG 小 25-50% |
| PNG 优化 | oxipng（Rust/WASM） | PNG 无损压缩，7 档级别，只减小体积不降画质 |
| 裁剪 | Canvas API | 宽高比约束裁剪 |
| 旋转 | Canvas API | 90 度步进旋转（0-360°） |
| 水印 | Canvas API | 文字水印：颜色、字号、透明度、角度 |
| EXIF | piexifjs | 查看与擦除 EXIF 元数据 |

拆成多个工具而不是一个大而全的页面，是因为每件事的输入参数完全不同——格式转换要批量调质量，裁剪要交互式选区，水印要排版参数。硬塞进一个页面只会得到一个谁都用不顺手的界面。

## 格式取舍

你实际会选的几种格式：

- **JPEG**：有损，不支持透明，适合照片。质量 80 是 Web 场景的最佳平衡点——视觉上跟 100 没区别但文件只有一半大。低于 60 就能看到瑕疵了。
- **PNG**：无损，支持完全 alpha 透明。最适合截图、logo、文字密集的图形和任何有锐利边缘的内容。照片场景下文件比 JPEG 大，但不会丢失任何细节。
- **WebP**：谷歌的格式。同时支持有损和无损，含透明通道，生成的文件比同等 JPEG/PNG 小 25-35%。浏览器支持已全面覆盖。
- **AVIF**：比 WebP 更好的压缩率（同等质量下通常再小 50%）。支持 HDR 和广色域。缺点是编码更慢，处理大图时你能感受到差别。

Canvas 本身不能编码 WebP / AVIF 的高压缩率变体，所以这两个格式走独立的 WASM 编码器工具。

## 缩放质量的原理

把图像缩小时，浏览器要决定每个输出像素由哪些源像素贡献。默认是双三次插值——邻近像素的加权平均——大多数情况下看起来不错。

放大时没有新增信息可用，结果会显得模糊。浏览器没法凭空补上源图中不存在的细节。如果你需要大幅放大一张图，最好用专门的 AI 超分辨率工具。

## 为什么在客户端处理

工具从不把你的图像发送到任何地方。这不只是隐私特性——也是性能特性。一张 20 MB 的照片上传要花几秒，下载结果又要花几秒。浏览器处理只要几毫秒。唯一的瓶颈是你设备的 CPU/GPU。

代价是：浏览器的图像编解码器是为速度优化，不是为把文件里每个字节都榨干。如果你需要极致压缩（比如生产环境的图像处理管道），服务器上跑 `imagemagick` 或 `sharp` 这类命令行工具效果更好。但日常一次性转换，浏览器绰绰有余。
