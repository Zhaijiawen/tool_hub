# X25519 技术背景

X25519 是 Daniel J. Bernstein 设计的现代密钥交换函数。它是在 Curve25519 上做的 ECDH，精简到最简单的 API：32 字节私钥加 32 字节公钥，输出 32 字节共享密钥。就这样。不用选曲线参数、不会忘记点验证、不用担心时序侧信道。

## 为什么 X25519 会诞生

传统 NIST 曲线上的 ECDH 有不少坑。你需要验证对方公钥在曲线上、不是无穷远点、你的实现不会从条件分支泄露时序信息。实现经常在这些地方出错。X25519 从设计上消除了这些问题：

- 每个 32 字节字符串都是有效的公钥。曲线的 clamping 操作确保如此。
- 函数天然是恒定时间的 -- 不会在秘密数据上产生分支。
- API 面积极小 -- 只有两个函数：标量乘法和基点乘法。

这就是 WireGuard 只使用 X25519 的原因。也是 Signal、WhatsApp 和大多数现代安全消息协议采用它的原因。

## Curve25519

底层曲线是 Curve25519：y^2 = x^3 + 486662x^2 + x，定义在素数域 GF(2^255 - 19) 上。素数是故意选的 -- 2^255 - 19 是小于 2^255 且模 4 余 3 的最大素数，这能使平方根计算高效。

曲线的协因子是 8，意味着全群大小是素数阶子群的 8 倍。X25519 的 clamping 操作（清除私钥低 3 位并设置高位）确保你留在素数阶子群中，避免小子群攻击。

## X25519 vs Ed25519

这两个经常被混淆。快速区分：

- **X25519**：密钥交换（Diffie-Hellman）。输入私钥和对方公钥，输出共享密钥。
- **Ed25519**：数字签名。输入私钥和消息，输出签名。

它们使用同一条底层曲线（Curve25519 及其双有理等价的 Edwards 形式），你可以在 X25519 和 Ed25519 密钥对之间转换。但它们是用于不同目的的不同函数。X25519 替代 ECDH；Ed25519 替代 ECDSA。

## 安全性

X25519 提供约 128 位安全性。运行 Shor 算法的量子计算机会破解它，但这对所有椭圆曲线密码都成立。对经典攻击者，没有比通用 Pollard's rho 算法（~2^128 操作）更快的已知攻击。

32 字节密钥非常小。一个 X25519 公钥能放进一条推文。这种紧凑性对嵌入式协议、二维码和任何带宽受限的场景都很重要。

## 采用情况

X25519 现已是 TLS 1.3 的强制要求。它是 WireGuard 唯一的密钥交换机制。Noise 协议框架默认使用它。libsodium、Go 标准库、Rust 的 x25519-dalek crate 以及所有主流密码库都支持它。对新的密钥交换实现，几乎没什么理由用别的。
