# CIDR 网段计算示例

实际工作中会遇到的子网划分场景。

## 家庭/办公网络（/24）

家里路由器的经典配置：

**输入：** `192.168.1.0/24`

| 字段 | 值 |
|---|---|
| 网络地址 | 192.168.1.0 |
| 广播地址 | 192.168.1.255 |
| 子网掩码 | 255.255.255.0 |
| 可用 IP 数量 | 254 |
| IP 范围 | 192.168.1.1 ~ 192.168.1.254 |
| 类型 | 私有地址（C 类） |

你家路由器多半就是在这个范围里通过 DHCP 分配地址，`.1` 或 `.254` 通常是网关。

## 企业内部网络（/16）

几千台设备的大办公室：

**输入：** `10.0.0.0/16`

| 字段 | 值 |
|---|---|
| 网络地址 | 10.0.0.0 |
| 广播地址 | 10.0.255.255 |
| 子网掩码 | 255.255.0.0 |
| 可用 IP 数量 | 65,534 |
| IP 范围 | 10.0.0.1 ~ 10.0.255.254 |
| 类型 | 私有地址（A 类） |

六万多个地址，够一个大型写字楼里所有笔记本、手机、打印机和 IoT 设备用了。

## 把 /24 对半分（/25）

两个部门要隔离，但只有一个 /24 网段怎么办？

| 子网 | 网络地址 | 广播地址 | 可用主机 |
|---|---|---|---|
| 上半段 | 192.168.100.0/25 | 192.168.100.127 | 126 个 |
| 下半段 | 192.168.100.128/25 | 192.168.100.255 | 126 个 |

每半段 126 个可用地址，子网掩码变成 `255.255.255.128`。

## 云服务 VPC 规划

一个多层应用的典型 VPC 布局：

```
VPC 总网段：10.0.0.0/16（共 65,534 个 IP）

├── 公有子网 A：10.0.0.0/20   （4,094 个 IP）对外服务
├── 公有子网 B：10.0.16.0/20  （4,094 个 IP）对外服务（跨可用区冗余）
├── 私有子网 A：10.0.32.0/20  （4,094 个 IP）应用层
├── 私有子网 B：10.0.48.0/20  （4,094 个 IP）应用层（跨可用区冗余）
└── 数据库子网：10.0.64.0/24  （254 个 IP） 数据层
```

应用子网用 /20 是为了扩容时不至于 IP 不够，数据库子网用 /24 是因为数据库实例一般不需要那么多。

## 点对点链路（/30）

路由器之间互联只需要 2 个地址：

**输入：** `10.1.1.0/30`

| 字段 | 值 |
|---|---|
| 网络地址 | 10.1.1.0 |
| 广播地址 | 10.1.1.3 |
| 可用主机 | 10.1.1.1 和 10.1.1.2 |
| 可用数量 | 2 |

P2P 链路上用比 /30 更大的前缀纯属浪费地址。

## IP 归属判断

**`10.50.20.100` 在 `10.50.0.0/16` 里吗？**
- 网段范围：`10.50.0.1` ~ `10.50.255.254`
- `10.50.20.100` 在范围内 -- 是。

**`172.31.255.250` 在 `172.16.0.0/12` 里吗？**
- 网段范围：`172.16.0.1` ~ `172.31.255.254`
- `172.31.255.250` 在范围内 -- 是。/12 覆盖 172.16.x.x 到 172.31.x.x。
